原生 Kotlin 工程，包名 `com.shaniu.companion`。当前源码版本
`0.7.28-shaniu-mimo-chat`（versionCode 58），Android 10+（minSdk 29），
compile/target SDK 35。App 只承担配置和控制：设备完成配置后独立运行语音，
关闭 App 不等于结束设备端交互会话。

v2.5 对话模型；已有设备配置不会因安装 App 自动改写。旧固件协商 MTU 71 时使用
67 B 有效数据，修复 68 B 分片重组超时；MTU 185 仍可发送 182 B，并未恢复全局
20 B 限速。真实手机安装、连接与语音证据见[夜间复测](../../docs/verification/bk7258/2026-11-03-feature-validation/README.md#夜间配置真人语音与-app-ble-跟进)。

## 当前界面

主导航为“设备、定制、更新、设置”。暖瓷白/墨色构成界面底色，设备眼睛是正常
状态下唯一彩色元素；只有认证会话和新鲜设备状态才能让眼睛呈现已连接。设备页显示
手机、傻妞和语音服务的链路；定制页集中外观、声音、唤醒及陪伴功能；电脑授权与
审批位于设置页。内容在平板和横屏中限制为 560dp 居中列，系统关闭动画时不播放
页面、导航和弹层动效。设计约束见 [DESIGN.md](DESIGN.md)。

## 默认表情

在“定制 → 默认表情”查看最近任务，再选择“刷新设备默认”读取设备保存的
素材。任务仍在执行时，可用“读取操作结果”继续确认；受理不是保存或显示完成。
先在资源更新中选择本地素材包，确认设备已安装同名素材后，才能将其设为默认。
本页按已安装素材名称切换，不上传本地文件，也不声称本地文件版本已经安装。

取消只适用于尚未提交的任务；资源释放失败可显式恢复，但原 UNKNOWN 结果
不会因此变成成功。断线/关闭页面不自动重发、更改默认或宣称远端已取消。
不支持默认选择协议的旧固件会明确提示，不回退到其他写入路径。

JVM/模拟器已覆盖本地草稿与页面重建；实际 BLE/板端流程另行验收。当前页面没有
已安装素材目录接口，仍需与手机 kind17 协议对应的固件；APK 不能补齐旧固件能力。

## 构建

安装 JDK 17、Android SDK Platform 35 及 Gradle 所需构建工具。
在 `local.properties` 指定自己的 SDK 路径，或使用标准 `ANDROID_HOME`；
不要提交个人路径、签名文件或 token。第一次构建需要获取依赖。

```bash
cd android/shaniu-companion
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。
不需要连接开发板，不需要 Beken SDK、私人训练数据、云 API key 或设备认证文件。
没有授权/配对设备时可查看界面，但不应伪造设备在线或设置成功。

安装到自己选择的手机：

```bash
adb -s <手机序列号> install -r app/build/outputs/apk/debug/app-debug.apk
```

已有认领数据的手机必须先确认 APK 签名兼容；不能用卸载、清数据或改签名绕过
安装问题。APK 编译/安装与真实 BLE、设备动作及 OTA 验收分别记录。
现有单元检查可用 `:app:testDebugUnitTest`，不是正常安装的强制前置，
也不代表射频、音频或烧录成功。

## 操作顺序

1. 打开蓝牙并授予系统要求的权限。新设备从“添加傻妞 · 扫码连接”进入，扫描
   设备屏幕认领码；已有绑定直接连接并认证，不重复认领。认领无需互联网。
2. 让板子扫描附近 Wi-Fi，填写网络配置与所选云服务凭据。默认使用 MiMo
   标准服务，也可填写兼容接口；请使用允许设备运行时调用的凭据。
   设备保存并返回结果后才显示成功。
3. 定制页提供表情、默认资源、唤醒模型与“回答与唤醒”入口；设置页提供云服务
   与模型、音量和记忆等入口，资源安装转到更新页。录音、播放或资源事务占用时
   如实显示暂不可操作，支持项以设备能力回读为准。
4. 正常使用说“你好，openvela”进入设备交互。App 不负责逐轮启动、停止、
   重连或录音转发。
5. 重启/短暂断连后重新认证并读取设备当前状态；超时的写操作不自动重发。
   删除手机绑定仅清除手机持有的连接资料，不能清除设备数据来冒充重新认证。

已有 owner 绑定不代表网络和语音服务已配置。11 月 3 日下午这台板的非敏感配置头
仅有 owner；随后已用绑定手机补齐网络和服务，更新对话模型并回读配置版本 5，
当晚完成一次真人语音回答。该次回答延迟较长，重启后的恢复仍需另验。
正常配置应确认保存与设备应用结果，再检查语音就绪；敏感配置页不录屏。

NFC 场景动作 7 已在 App 和板端源码中接入，可把卡片映射为按 App ID 哈希启动一个
已安装原生功能；它不取代 BLE 认领、owner 认证或签名安装。本轮仅完成主机、JVM
与构建检查，尚未用真实卡片、手机和板子验证，不把“碰一碰启动”列为实板通过。

## 原生功能与电脑审批

- 原生功能页读取设备目录、展示 ABI/权限/故障和上次结果，经临时 HTTPS 来源安装
  第一方签名包；设备仍独立验签、检查防回滚并回读终态。ABI 3 在 ABI 1/2 兼容基础
  上增加可信时间、保存进度、结果标签、语音/Agent 启停和每日定时。
- 正式产品配置的发布者指纹当前为空，因此安装会被设备拒绝；诊断构建和主机测试
  使用的测试密钥不是产品密钥。选择发布密钥前，App 界面存在不等于商店已开放。
- “电脑审批”只允许已有 `tasks` grant 的电脑发起，只有手机 owner 能决定。手机
  显示 Agent、目标与操作原文；超时、请求变化、授权变化和无效签名一律按拒绝处理。

11 月 3 日实板已确认审批无人批准时过期、命令不执行，
[回执](../../docs/verification/bk7258/2026-11-03-feature-validation/evidence/approval-expired.json)
保留在对应验证目录。手机批准/拒绝、真实 BLE 安装与动作 7 刷卡启动仍未验收。
单次审批是独立流程；普通已有授权的电脑任务与设备日常语音不用逐次找手机批准。

## 连接与安全边界

- `ProvisionGattSession` / `DeviceControlSession` 串行化命令，连接代次防止
  旧回调污染新会话；设置 ACK 与后续状态确认是两件事。
- BLE 承载设备认证、受保护配置和控制；TLS 校验设备证书 pin、有效期及用途。
  已保存认领凭据不等于设备当前在线。
- 控制凭据由 Android Keystore 保护的 AES-GCM 存储保存，不硬编码进 APK；
  云凭据不明文回读，不输出到日志。UI 明确区分未就绪、忙、失败与断连。
- 默认不需要 Gateway。历史 console-v1 类和测试夹具不构成当前产品交互路径。
  不启用它们来解决编译或连接问题。
- 可选持久记忆由设备加密存储并投影回官方 Session；手机不托管对话历史。
  删除/禁用需设备完成并确认，收到请求不等于已经持久化。

## 认领与设备身份

正常入口是设备页的“添加傻妞 · 扫码连接”。首启身份和屏幕认领码由设备负责，
App 以认领码提供的身份与持有证明核对设备，再经认证 BLE 配置网络与云服务。
扫描到广播不等于身份已验证；认领结果不确定时使用“核对认领结果”，不重新造身份。

已有绑定、Android Keystore 与设备 owner 必须保留；换手机、清数据或重置是不同
操作，不能用来绕过连接问题。设备 TLS 私钥、云凭据和 OTA 签名根彼此独立。
APK/固件构建不需要作者的设备授权文件。

旧版导入授权资料和串口身份供给属于兼容维修路径；历史输入与判据保留在
[9 月 20 日部署快照](../../docs/platforms/bk7258/first-deployment-inputs.md)，
不作为新设备的默认步骤。授权 JSON 含持有秘密，不进入 Git、APK、比赛 ZIP 或
公开链接；已有设备不重新生成或替换身份。实际首启/认领范围见
[当前板级验收](../../boards/bk7258/CONFIGS.md)。

## 眼睛资源与真实 App OTA

眼睛资源和固件均由手机临时 HTTPS 服务通过 Wi-Fi 供设备下载；
BLE 只传已认证的来源描述、CA、完整性参数及控制状态，不传整包固件。
手机与设备需网络可达，并保持供包期间 App 前台和网络可用。
不公开供包端口、不关闭证书验证，不假定中断传输支持断点续传。

- 眼睛包：`.bkep`，由现有
  [资源工具](../../app/bk7258/assets/display/README.md)生成；
  设备验证格式/完整性，经唯一存储 owner 安装并回读。
- 固件包：`.bkpack`，必须匹配板型、布局、现有签名信任和安全计数。
  `OTA_START` 只表示接受请求；重启后确认设备身份、目标版本/计数和
  trial confirmed，才显示升级成功。
  来源准备期间若状态读取在途，先等读回并重新核对能力，再发送首个请求；
  离开前台或连接变化会取消尚未发送的准备，不自动重发升级。
  设备拒绝取消时继续提供已接受的固件来源，等待设备终态；取消请求不等于
  取消成功，不能靠停止手机供包中断设备更新。
  来源记录上传期间允许请求取消，由当前指令回执后串行发送；收到 START 成功
  回执即记录来源已接受，即使取消与该回执竞争或取消发送失败，也保留来源等待状态确认。
- [2026-10-18 实机记录](../../docs/verification/bk7258/2026-10-18-stability-and-phone-hil.md)保留了取消拒绝后的供包闭环、APK54回归、APK55/768–769蓝牙诊断，以及APK56解除旧更新等待后实际启动770的结果；770固件已确认，但广播停止超时导致OTA后自动重连失败，底层问题仍未通过实机验收。来源上传期取消也尚未实测。
- 634 已完成用户发起的实际 App OTA：约 93% 断连，重启回读后 100% 成功。
  635 新增 runtime Skill，App 控制/OTA 行为路径未改，**本轮未在 635 重测**。
- 635 full 包与 OTA-only 包不同：full 构建 floor 635；OTA-only 不替换 BL1/BL2。
  同板恢复包含身份/数据，不能作为公共 APK 附件或其他设备的升级输入。

## 源码与复现

| 位置 | 职责 |
|---|---|
| `MainActivity.kt` | 前台控制、设置与当前状态展示 |
| `provision/` | 扫描、TLS/GATT、所有权、串行控制协议与连接会话 |
| `ota/OtaPackageServer.kt` | 短生命周期本地 HTTPS 供包 |
| `EyePack.kt` | 眼睛资源输入与完整性边界 |
| `app/src/main/assets/wake-models/` | 随 App 的公开内置唤醒包 |
| `app/src/main/res/` | 应用图标与 UI 资源 |

App 工程与固件适配在同一团队仓版本管理，不额外建立 App Git 仓或 NuttX linkfile。
官方 Agent 是工作区另一依赖项目，其来源与固定提交由团队 manifest 维护；
它不是 Android Gradle 依赖。来源和许可见
[App 来源记录](SOURCE_PROVENANCE.md)与[项目来源记录](../../SOURCE_PROVENANCE.md)。

已完成校验的本地眼睛素材选择会保存在 Activity 状态中；页面重建时重新校验
文件摘要和包格式，再恢复本地缓存。单包沿用 128 KiB 上限，不保存设备 Key、
URI 授权或安装事务。恢复选择不会自动上传或设为设备默认；损坏/超长输入
不会覆盖上一份有效选择。退出后重新冷启动、系统主动丢弃任务状态时仍需
重新选文件，不把 Activity 状态保存承诺为永久素材库。

“限时表情试用”可选择设备当前默认素材，或设备上与本地所选文件同名的
已安装素材。试用名称不代表已上传或版本一致；设备缺包时明确失败，不自动
回退试用默认包。选择来源与时长草稿可跨页面和 Activity 重建；试用仍由
设备计时，取消须等待恢复确认，新默认会使旧试用失效。
