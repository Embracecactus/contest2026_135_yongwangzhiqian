# 发布中文 PR

执行时先读同仓提供的
[fork-change-publication](../fork-change-publication/SKILL.md)。此 Skill 只补充
中文表达和交接，不再维护另一套 Git 操作流程，也不依赖作者的用户目录。
需要单独分发时一并保留这个相邻依赖；缺少依赖不代表发布检查已完成。

## 权限与项目约束

- 从请求、仓库规则、当前 remote URL 和分支引用确定目标仓库、基线与 head；
  remote 名称、作者账号及历史比赛分支均不是默认值。合入后仍按实际拓扑工作，
  不要求后来者使用原作者的 fork。
- 提交、推送、创建 PR、合并分别沿当前明确授权执行；仅准备中文文案不执行这些动作。
- 保留无关脏树。默认不改写历史、不强推、不自动 rebase/merge、不清理文件。
  用户通常自行在网页创建/合并 PR；未要求时仅交付可粘贴内容。
- 依据项目产物目录排除私钥、凭据、设备备份、私人原始日志和无关生成物。
  开发日志只在已明确的交付范围内处理，不顺带暂存。

## 中文 PR 输出

按通用流程完成请求范围内的检查/发布。基于已核验的官方基线与实际发布 HEAD
生成内容；未提交文件不能写成已在该 PR 中。输出：

- 中文 PR 标题：遵循仓库现有格式；采用 Conventional Commit 时保留类型/范围，摘要使用中文。
- 中文正文包含具体问题、实际修改、相关验证、边界与未完成项；简单变化可用
  连贯短段落，不机械展开长模板。只写有证据的构建、版本和板端结果。
- 若有明确延后、硬件夹具依赖、破坏性测试或未覆盖项，单独列明，不能隐去。
- 依据核实的 base/head 给出 Compare 或实际 PR 链接，不填写个人账号占位为事实。
- 对已执行的动作报告本地提交 SHA、远程分支 SHA 与推送/PR 状态；未执行则明确标注。

最终区分草稿、已提交、已推送、已建 PR 和已合入，不把任一阶段写成后续阶段完成。
