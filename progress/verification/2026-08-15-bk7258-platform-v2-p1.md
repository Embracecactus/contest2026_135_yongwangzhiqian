## Scope

P1 adds a host-only strict JSON composition resolver in the existing
`board/bk7258/scripts` path.  It validates board/product/fragment schemas,
resolves exactly one product board and one CP/AP/BL2 role, rejects conflicting
symbols and dependency cycles, and emits deterministic IR with a SHA-256
identity.  The CMake output is a source-view candidate; Classic remains an
adapter-only feasibility report.  No legacy config, production builder,
official tree, SDK byte or hardware state was changed.

## Negative coverage

The fast tests cover duplicate JSON keys, invalid board RTS-reset binding,
board mismatch, mode mismatch, unknown product, conflicting explicit symbol
values and mutated IR identity.  The resolver has no implicit board/profile
fallback.  Full adversarial and legacy regression suites remain consolidated
review work.

## Boundaries

The Classic report records feasibility and required isolation only; it is not
a build or parity claim.  P2 must add immutable SDK metadata and provenance
verification without copying archives or mutating the designated private
mirror.
