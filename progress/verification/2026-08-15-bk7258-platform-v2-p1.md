## Scope

P1 adds a host-only strict JSON composition resolver in the existing
`board/bk7258/scripts` path.  It validates the versioned board/product/mode/
role/fragment schema, resolves exactly one product board and one CP/AP/BL2
role, rejects conflicting symbols and dependency cycles, and emits
deterministic IR with a SHA-256 identity.  The CMake adapter keeps the
existing board/chip source tree read-only while creating a role-local build
view and forbidding a shared `.config`; Classic remains an unproven,
adapter-only feasibility report.  No legacy config, production builder,
official tree, SDK byte or hardware state was changed.

## Negative coverage

The fast tests cover duplicate JSON keys, invalid board RTS-reset binding,
board mismatch, mode mismatch, unknown product, conflicting explicit symbol
values, mutated IR identity, isolated role-view policy and the explicit
Classic non-proof status.  The resolver has no implicit board/profile
fallback.  Full adversarial and legacy regression suites remain consolidated
review work.

## Boundaries

The Classic report records feasibility and required isolation only; its
machine-readable `proven` and `isolation_proven` values are both `false`, so it
is not a build or parity claim.  P2 must add immutable SDK metadata and
provenance verification without copying archives or mutating the designated
private mirror.
