# BK7258 platform-v2 P4 ownership and resource-graph verification

- Date: 2026-08-15
- Branch: `refactor/bk7258-platform-v2`
- Scope: machine-readable ownership boundaries, compatibility inventory, and
  paired BL1/BL2/CP/AP resource resolution.

## Implemented

- `bk7258_layer_ownership.json` and its schema now express only the official
  Architecture -> Chip/SoC -> Board hierarchy.  Architecture is upstream
  NuttX and `external_upstream_needed`; no public NuttX/common code is patched.
  `vendor_common_glue`, `build_adapter` and `migration_pending` are internal
  responsibility tags, not peer formal layers.
- The ownership split keeps BK7258-intrinsic AP topology/lifecycle,
  mailbox/IPI/shared memory, RPTUN transport, clock/power lower-halves and
  cross-core mechanisms in Chip.  Board owns pins, bindings, external devices,
  linker/configuration and bring-up; existing `src/` glue is classified per
  symbol rather than moved wholesale.
- The four official board init phases are recorded.  Production validation
  auto-start is explicitly `migration_pending` away from Chip toward existing
  Board bring-up.
- `bk7258_compatibility_migration_ledger.json` records representative current
  files and Kconfig symbols as `inventory-only`; it performs no broad move and
  creates no layer directory.
- `bk7258_resource_graph_t5ai_core.json` covers the exact board, product,
  mode, BL1/BL2/CP/AP pair, download/boot/hold/runtime/suspend/restart phases,
  pin/function claims, `/dev` minor claims, IRQ/DMA/clock/power resources,
  content-addressed SDK singletons, mailbox provides/requires, memory/PSRAM,
  fitted/unknown BOM state, and temporal handoffs.
- The graph resolver binds to the existing P3 build plan, requires exactly one
  board with fallback forbidden, and retains `max_instances=1` plus explicit
  ownership for SDK singleton resources.  It emits a distinct resolved graph
  identity without downloading, copying or uploading SDK bytes.
- `bk7258_framework.py` exposes `layer-check`, `migration-check`,
  `resource-check`, and `resource-resolve` as host-only compatibility commands.
  P1-P3 CMake/Classic tools remain adapters over existing semantics; artifact
  mapping is `libarch.a`, `libboards.a`, `vela_*.bin`, with `.bkpack` only a
  later additive vendor extension.
