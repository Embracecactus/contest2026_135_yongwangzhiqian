# BK7258 platform-v2 P6 package metadata verification

- Date: 2026-08-15
- Branch: `refactor/bk7258-platform-v2`
- Scope: strict metadata-only `bkpack` preparation and verification.

## Implemented

- `bk7258_bkpack_schema.json` rejects unknown/duplicate structure and records
  separate application/factory kinds and plans, exactly one named apps plan,
  standard artifacts, additive `.bkpack`, source-build identity, SDK lock,
  partition/range, tool and trust metadata.
- `pack-prepare` resolves the existing product/build plan and partition CSV,
  maps `libarch.a`, `libboards.a`, `vela_bl1.bin`, `vela_bl2.bin`,
  `vela_cp.bin` and `vela_ap.bin`, and emits no image bytes.
- `pack-verify` checks identity bindings and rejects extra, overlapping,
  outside or ambiguous artifacts/ranges. Signing, private keys, network,
  Flash and hardware are not accessed; `hardware_verified` stays false.

No SDK/object/image bytes were read or copied, and no sign, key, network,
Flash or hardware operation was performed.

Later packaging review corrected the artifact terminology without changing
this historical P6 result: `vela_bl1.bin`/`vela_bl2.bin` were metadata aliases,
not openvela standard outputs.  The current contract names Beken boot-chain
payloads `bootloader.bin`/`bl2.bin`; see the additive delivery-package record.
