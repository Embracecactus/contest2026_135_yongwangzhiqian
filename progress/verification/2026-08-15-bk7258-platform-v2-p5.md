# BK7258 platform-v2 P5 validation-runner verification

- Date: 2026-08-15
- Branch: `refactor/bk7258-platform-v2`
- Scope: metadata-driven `bkvalidate` skeleton and legacy validation mapping.

## Implemented

- `board/bk7258/scripts/bk7258_validation_descriptors.json` is a versioned,
  identity-bound descriptor set.  Each descriptor carries id/version/role,
  typed requirements, category, timeout, prepare/run/cancel/cleanup, status,
  global resource claims and an `app/hello_app` entrypoint.
- `bk7258_validation.py` rejects duplicate/unsafe descriptors, vendor or
  chip/board-private runner commands, non-`app/hello_app` entrypoints and
  incomplete mappings.  It verifies all 27 frozen legacy profiles map to
  family/resource mode/validation suite; the frozen ledger remains
  `consolidation-review`, while the new path is explicitly
  `migration_pending`.
- `app/hello_app/bkvalidate_main.c` exposes `list`, `run <id>` and
  `all-compatible`.  It serializes claims within the process, probes only
  public device paths, emits stable JSON outcomes, and returns `SKIP` for
  incompatible, interactive, fixture, destructive-fault or planned cases.
  No vendor SDK call or production validation auto-start was changed.
- Kconfig, Classic Make and CMake wiring is opt-in through
  `CONFIG_BK7258_BKVALIDATE`; existing hello-app diagnostics remain intact.
