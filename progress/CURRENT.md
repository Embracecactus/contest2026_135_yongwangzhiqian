## Active objective

The working branch is `feat/bk7258-t5-board-tf`; its branch HEAD is the
publication checkpoint for the completed T5-Board TF/SDIO stage.  The one-bit

## Completed in the working tree

- Board pin ownership is fixed at CLK/CMD/D0/D1/D2/D3 =
  P2/P3/P4/P5/P10/P11; optional U3 must remain NC.
- P6 was high with the card inserted and high after removal.  Applying the
  SDK-equivalent input/pull-up configuration did not change the removed state,
  so P6 is not a usable card-detect source on this board and polarity reversal
  is explicitly rejected.
- SDIO controller logic remains in `chip/ap`; the T5-Board TF slot, pins,
  fixed-media policy, S1 route and validation options now live in the board
  binding.  Profiles select the board slot rather than the hidden chip host.
- One-bit advertises `SDIO_CAPS_1BIT_ONLY`.  The reserved four-bit source path
  would advertise `SDIO_CAPS_4BIT` and leave ACMD6 to NuttX, but both the build
  preflight and wrapper reject it with the current one-bit SDK bundle.
- Fixed-media profiles explicitly disable `MMCSD_HAVE_CARDDETECT`; status is
  always present after board initialization and no P6 polling worker is linked.
- Separate MCUboot validation profiles enforce the S1 route contract.
- The FAT validator performs two bounded mount/write/fsync/reopen/read/verify/
  remove/unmount cycles on a card inserted before reset; it never formats media.
  It handles raw FAT/DOS MBR directly and, for GPT media, selects the first
  partition that the FAT driver actually accepts rather than assuming the
  largest partition is FAT.
- The controller keeps the continuous card clock used by the official SDK
  across CMD7 and the transfer-clock switch.  Command polling no longer clears
  a coalesced data IRQ, and the SDK-specific CMD12 reset/gate sequence remains
  bounded to CMD12.
- TF-enabled T5 profiles set `MMCSD_MULTIBLOCK_LIMIT=1`.  This uses NuttX's
  supported single-block path and avoids the immutable CPU-FIFO SDK's observed
  second-block pre-read overflow while retaining the official 20 MHz clock.
- The final one-bit CP/AP pair passes profile preflight and signed build.  The
  four-bit pair now fails preflight deliberately instead of generating a
  controller/card width mismatch.
- The final one-bit MCUboot pair completed a full signed dual-image build with
  version `18.6.60` and security counter `114`.  SDK checksum, partition,
  Factory and RPTUN layout checks passed; the public trust-contract SHA-256
  remained `b2a8e35256b97a0dd4fef6da253225d770001f4f20743d44bf8e9cc5f3b97c7e`.
- Trust-preflighted apps-only download wrote only CP `0x11000/0x3d000` and AP
  `0x165000/0x28000`; the installed boot chain and data regions were untouched.
- Non-halting J-Link diagnostics at `0x28054b08` report state `PASS`, result 0,
  final stage 10, width 1, cycles 2, bytes `0x2000` and checksum `0x17c60dc5`.
  The Home Assistant OS GPT card selected `/dev/mmcsd0p1` (`hassos-boot`) as
  the mountable FAT partition, and the temporary validation files were removed.
- `build_dual_image.sh --help` is side-effect free and unknown arguments now
  fail before any configuration or build.
- The two development signing identities were originally generated by the
  project workflow and left only under temporary names.  When those names
  disappeared, explicitly approved current-domain alias copies were found and
  matched against all three recorded public fingerprints.  The working names
  are restored for this session; no replacement key or trust-root rotation was
  performed.
