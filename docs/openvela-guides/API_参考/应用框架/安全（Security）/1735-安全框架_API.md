# 安全框架 API（Security Framework API）

openvela 安全框架基于 MiTEE（可信执行环境）提供安全存储、密钥管理和安全支付等能力，遵循 GlobalPlatform（GP）TEE 标准。

本文档涵盖以下内容：

  - MiTEE CA 应用级 API 接口（SST 安全存储、三元组、微信/支付宝支付、PIN 码）
  - MiTEE Rootkey API 接口
  - GP TEE Client API（REE 侧，供 CA 调用）
  - GP TEE Internal API（TEE 侧，供 TA 实现使用）

头文件：<span class="reference">frameworks/security/include/</span> 下的各 CA 头文件（<span class="reference">comsst\_ca\_api.h</span> / <span class="reference">triad\_ca\_api.h</span> 等），以及 <span class="reference">\<sys/boardctl.h\></span>（Rootkey）、OP-TEE <span class="reference">\<tee\_client\_api.h\></span>（TEE Client）、<span class="reference">\<tee\_internal\_api.h\></span>（TEE Internal）。

# openvela 实现说明

  - **安全方案双轨并存**：openvela 提供两套可选的安全能力——
      - **基于 MiTEE 的 TEE 方案**（本文主要内容）：面向需要硬件级可信执行环境的场景
      - **Android Keystore 方案**（见"Android Keystore Client API"小节）：移植自 AOSP，面向只需密钥管理与安全存储的轻量场景
  - **基于 MiTEE**：openvela 的 TEE 实现，与 OP-TEE 兼容，遵循 GlobalPlatform（GP）规范
  - **两侧运行时**：
      - **REE 侧**（Rich Execution Environment）：运行 CA（Client Application），通过 <span class="reference">libteec</span> 发起 TEE 请求
      - **TEE 侧**（Trusted Execution Environment）：运行 TA（Trusted Application），由 <span class="reference">miteed</span> 服务器调度
  - **通信通道**：CA 与 TA 之间通过 rpmsg socket 进行数据交换
  - **API 层次**：
      - 应用级 CA API（位于 <span class="reference">frameworks/security/ca/</span>）封装常见的安全业务（SST、三元组、支付、PIN）
      - GP TEE Client API（REE 侧）提供 GP 标准的 Context/Session 管理与命令调用
      - GP TEE Internal API（TEE 侧）提供 TA 实现者可调用的内存/对象/加解密能力
  - **密钥根**：Rootkey 在工厂阶段一次性写入，运行时不可变，所有派生密钥都从 Rootkey 推导

# 通用安全存储 SST CA API

对安全存储（Secure Storage，SST）分区执行读写操作。实现位于 <span class="reference">frameworks/security/ca/comsst</span>。

## comsst\_data\_read

    uint32_t comsst_data_read(uint8_t *scope, uint8_t *name, bool is_deletable,
                              uint8_t *buff, uint32_t *out_len);

从 SST 分区读取一条数据记录。

**参数**：

  - <span class="reference">scope</span> 命名空间（范围标识），用于区分不同业务。
  - <span class="reference">name</span> 记录名称。
  - <span class="reference">is\_deletable</span> 该记录是否允许被用户侧删除。
  - <span class="reference">buff</span> 输出缓冲区，接收读取到的数据。
  - <span class="reference">out\_len</span> 输入输出参数，输入为缓冲区大小，输出为实际读取长度。

**返回值**：

成功时返回 <span class="reference">TEE\_SUCCESS</span>（<span class="reference">0</span>），失败时返回 TEE 错误码。

## comsst\_data\_write

    uint32_t comsst_data_write(uint8_t *scope, uint8_t *name, bool is_deletable,
                               uint8_t *buff, uint32_t len);

向 SST 分区写入一条数据记录。

**参数**：

  - <span class="reference">scope</span> 命名空间。
  - <span class="reference">name</span> 记录名称。
  - <span class="reference">is\_deletable</span> 该记录是否允许被用户侧删除。
  - <span class="reference">buff</span> 要写入的数据缓冲区。
  - <span class="reference">len</span> 数据长度。

**返回值**：

成功时返回 <span class="reference">TEE\_SUCCESS</span>，失败时返回 TEE 错误码。

## comsst\_data\_delete

    uint32_t comsst_data_delete(uint8_t *scope, uint8_t *name, bool is_deletable);

删除 SST 分区中的一条记录。

**参数**：

  - <span class="reference">scope</span> 命名空间。
  - <span class="reference">name</span> 记录名称。
  - <span class="reference">is\_deletable</span> 该记录的可删除属性，需与写入时一致。

**返回值**：

成功时返回 <span class="reference">TEE\_SUCCESS</span>，失败时返回 TEE 错误码。

## is\_comsst\_data\_exited

    uint32_t is_comsst_data_exited(uint8_t *scope, uint8_t *name, bool is_deletable);

查询 SST 分区中是否存在指定记录。

**参数**：

  - <span class="reference">scope</span> 命名空间。
  - <span class="reference">name</span> 记录名称。
  - <span class="reference">is\_deletable</span> 可删除属性。

**返回值**：

存在时返回 <span class="reference">TEE\_SUCCESS</span>，不存在时返回对应错误码。

## comsst\_data\_verify

    uint32_t comsst_data_verify(uint8_t *scope, uint8_t *name, bool is_deletable,
                                uint8_t *buff, uint32_t len);

比较传入数据与 SST 中已存储数据是否一致。常用于校验应用端持有的副本是否为最新。

**参数**：

  - <span class="reference">scope</span> 命名空间。
  - <span class="reference">name</span> 记录名称。
  - <span class="reference">is\_deletable</span> 可删除属性。
  - <span class="reference">buff</span> 待比较的数据。
  - <span class="reference">len</span> 数据长度。

**返回值**：

一致时返回 <span class="reference">TEE\_SUCCESS</span>，不一致或失败时返回错误码。

# MiTEE Rootkey 管理

Rootkey 是 TEE 安全体系的**信任根密钥**，用于派生其他密钥。该密钥在工厂阶段一次性写入，运行时由 TEE OS 读取使用。

## boardctl\_BOARDIOC\_UNIQUEKEY

    #include <sys/boardctl.h>
    
    boardctl(BOARDIOC_UNIQUEKEY, tmp_key);

TEE OS 中的 TEE Server（<span class="reference">miteed</span>）通过 <span class="reference">boardctl</span> 系统调用读取 Rootkey。

**参数**：

  - <span class="reference">BOARDIOC\_UNIQUEKEY</span> 固定命令字。
  - <span class="reference">tmp\_key</span> 输出缓冲区指针，接收 Rootkey 内容。

**返回值**：

成功时返回 <span class="reference">0</span>，失败时返回负值并设置 <span class="reference">errno</span>。

**注意**：

  - 只有 TEE OS 侧允许调用本接口；REE 侧应用无法访问 Rootkey。

## rootkey\_provision

    norflash_api_security_register_erase(HAL_FLASH_ID_0, 2048, 32);
    norflash_api_security_register_write(HAL_FLASH_ID_0, 2048, rn, 32);
    norflash_api_security_register_lock(HAL_FLASH_ID_0, 2048, 32);

Rootkey 仅在工厂版本中、TEE OS 首次启动时执行写入。典型流程为"擦除 → 写入 → 锁定"三步：

**参数**（以 <span class="reference">norflash\_api\_security\_register\_\*</span> 为例）：

  - <span class="reference">HAL\_FLASH\_ID\_0</span> Flash 设备标识。
  - <span class="reference">2048</span> 安全寄存器起始偏移。
  - <span class="reference">32</span> 字节长度（256 位）。
  - <span class="reference">rn</span> 写入时提供的 Rootkey 数据缓冲区。

**注意**：

  - 一旦执行 <span class="reference">\_lock</span>，该区域永久锁定无法再次写入，必须保证写入数据的正确性。
  - 生产设备永远不应包含调用上述接口的代码。

# Android Keystore Client API

**本节介绍的 Keystore 是一套独立于 MiTEE 的安全方案**，源码移植自 Android Keystore 服务框架，遵循 Keystore/Keymaster 标准接口。其中 Keymaster 层支持多种实现方式，包括对接 MiTee、纯软件实现以及为安全芯片（SE）定制的实现。

openvela Keystore 向上层以 Keystore C API 的方式，为账号 SDK 等应用场景提供密钥管理与安全存储能力，使用方无需关注底层的硬件差异和具体存储细节。

头文件：<span class="reference">\#include \<keystore/client.h\></span>

源码路径：<span class="reference">external/android/system/security/keystore/</span>

## Keystore 使用约定

  - **存储单元**：每条数据通过 <span class="reference">name</span> 字符串作为唯一标识
  - **命名规则**：<span class="reference">name</span> 长度上限为 <span class="reference">CONFIG\_NAME\_MAX - 12</span>；若包含特殊字符（ASCII <span class="reference">0</span> 至 <span class="reference">\~</span> 范围），每个字符按 2 字节计算
  - **返回值约定**：所有接口成功时返回 <span class="reference">KEYSTORE\_NO\_ERROR</span>（值为 <span class="reference">1</span>），失败时返回大于 <span class="reference">1</span> 的错误码
  - **内存管理**：<span class="reference">keyStoreGet</span> 返回的数据由内部分配，调用方需用 <span class="reference">free()</span> 释放

## keyStoreInsert

    int keyStoreInsert(const char *name, size_t nameLength,
                       const uint8_t *item, size_t itemLength);

将一条数据项写入 Keystore，数据在 Keystore 内部加密存储。

**参数**：

  - <span class="reference">name</span> 数据项名称。需唯一，受 <span class="reference">CONFIG\_NAME\_MAX - 12</span> 长度限制。
  - <span class="reference">nameLength</span> 名称长度（字节）。
  - <span class="reference">item</span> 要写入的数据缓冲区。
  - <span class="reference">itemLength</span> 数据长度（字节）。

**返回值**：

成功时返回 <span class="reference">KEYSTORE\_NO\_ERROR</span>，失败时返回其他 <span class="reference">KEYSTORE\_\*</span> 错误码。

**参数**：

  - <span class="reference">name</span> 数据项名称。
  - <span class="reference">nameLength</span> 名称长度。

**返回值**：

存在时返回 <span class="reference">KEYSTORE\_NO\_ERROR</span>，不存在或失败时返回其他 <span class="reference">KEYSTORE\_\*</span> 错误码。

## keyStoreReset

    int keyStoreReset(void);

删除当前应用在 Keystore 中的**所有**数据项。

**返回值**：

成功时返回 <span class="reference">KEYSTORE\_NO\_ERROR</span>，失败时返回其他 <span class="reference">KEYSTORE\_\*</span> 错误码。

**注意**：

  - 该操作不可撤销，仅作用于当前应用的命名空间。

# GP TEE Client API（REE 侧）

以下接口遵循 GlobalPlatform TEE Client API 规范，由 CA 在 REE 侧调用，用于与 TEE 建立上下文、打开会话、执行命令。

## TEEC\_InitializeContext

    TEEC_Result TEEC_InitializeContext(const char *name, TEEC_Context *context);

初始化一个 TEE 上下文，建立 CA 与指定 TEE 之间的连接。

**参数**：

  - <span class="reference">name</span> 零结尾字符串，标识要连接的 TEE。当前实现仅支持 <span class="reference">NULL</span>，表示连接默认 TEE。
  - <span class="reference">context</span> 待初始化的上下文结构体指针。

**返回值**：

成功时返回 <span class="reference">TEEC\_SUCCESS</span>，失败时返回其他 <span class="reference">TEEC\_Result</span> 错误码。

## TEEC\_FinalizeContext

    void TEEC_FinalizeContext(TEEC_Context *context);

销毁已初始化的 TEE 上下文，关闭 CA 与 TEE 之间的连接。

**参数**：

  - <span class="reference">context</span> 要销毁的上下文。

**注意**：

  - 调用前必须确保所有关联的会话已关闭、所有共享内存已释放。

## TEEC\_OpenSession

    TEEC_Result TEEC_OpenSession(TEEC_Context *context,
                                 TEEC_Session *session,
                                 const TEEC_UUID *destination,
                                 uint32_t connectionMethod,
                                 const void *connectionData,
                                 TEEC_Operation *operation,
                                 uint32_t *returnOrigin);

在 CA 与指定 TA 之间打开一个新会话。

**参数**：

  - <span class="reference">context</span> 已初始化的 TEE 上下文。
  - <span class="reference">session</span> 待初始化的会话结构体指针。
  - <span class="reference">destination</span> 目标 TA 的 UUID。
  - <span class="reference">connectionMethod</span> 连接方式。
  - <span class="reference">connectionData</span> 连接相关数据（当前未使用，应传 <span class="reference">NULL</span>）。
  - <span class="reference">operation</span> 操作参数结构体；若不需要传参，可传 <span class="reference">NULL</span>。
  - <span class="reference">returnOrigin</span> 输出参数，错误发生时返回错误来源。

**返回值**：

成功时返回 <span class="reference">TEEC\_SUCCESS</span>，失败时返回其他 <span class="reference">TEEC\_Result</span> 错误码。

## TEEC\_CloseSession

    void TEEC_CloseSession(TEEC_Session *session);

关闭已打开的 TA 会话。

**参数**：

  - <span class="reference">session</span> 要关闭的会话。

## TEEC\_InvokeCommand

    TEEC_Result TEEC_InvokeCommand(TEEC_Session *session,
                                   uint32_t commandID,
                                   TEEC_Operation *operation,
                                   uint32_t *returnOrigin);

在指定会话中调用 TA 命令。

**参数**：

  - <span class="reference">session</span> 已打开的会话句柄。
  - <span class="reference">commandID</span> TA 内部的命令 ID。
  - <span class="reference">operation</span> 操作参数结构体；若不需要传参，可传 <span class="reference">NULL</span>。
  - <span class="reference">returnOrigin</span> 输出参数，错误发生时返回错误来源。

**返回值**：

成功时返回 <span class="reference">TEEC\_SUCCESS</span>，失败时返回其他 <span class="reference">TEEC\_Result</span> 错误码。

## TEEC\_AllocateSharedMemory

    TEEC_Result TEEC_AllocateSharedMemory(TEEC_Context *context,
                                          TEEC_SharedMemory *sharedMem);

在指定 TEE 上下文范围内分配一块共享内存。

**参数**：

  - <span class="reference">context</span> 已初始化的 TEE 上下文。
  - <span class="reference">sharedMem</span> 待分配的共享内存结构体指针。

**返回值**：

成功时返回 <span class="reference">TEEC\_SUCCESS</span>；内存不足时返回 <span class="reference">TEEC\_ERROR\_OUT\_OF\_MEMORY</span>；其他失败返回对应 <span class="reference">TEEC\_Result</span> 错误码。

## TEEC\_RegisterSharedMemory

    TEEC_Result TEEC_RegisterSharedMemory(TEEC_Context *context,
                                          TEEC_SharedMemory *sharedMem);

将一块**调用方已分配**的内存注册为共享内存。与 <span class="reference">TEEC\_AllocateSharedMemory</span>（由框架分配）不同，本接口允许 CA 复用已有内存缓冲区作为 TEE 通信数据区。

**参数**：

  - <span class="reference">context</span> 已初始化的 TEE 上下文。
  - <span class="reference">sharedMem</span> 共享内存结构体指针，调用方应预先填写 <span class="reference">buffer</span>、<span class="reference">size</span> 和 <span class="reference">flags</span> 字段。

**返回值**：

成功时返回 <span class="reference">TEEC\_SUCCESS</span>，失败时返回对应 <span class="reference">TEEC\_Result</span> 错误码。

## TEEC\_ReleaseSharedMemory

    void TEEC_ReleaseSharedMemory(TEEC_SharedMemory *sharedMemory);

释放或注销先前分配的共享内存块。对 <span class="reference">TEEC\_AllocateSharedMemory</span> 分配的内存会释放，对 <span class="reference">TEEC\_RegisterSharedMemory</span> 注册的内存只做注销（不释放调用方的缓冲区）。

**参数**：

  - <span class="reference">sharedMemory</span> 待释放的共享内存结构体指针。

## TEEC\_RequestCancellation

    void TEEC_RequestCancellation(TEEC_Operation *operation);

请求取消一个正在执行的 <span class="reference">TEEC\_OpenSession</span> 或 <span class="reference">TEEC\_InvokeCommand</span> 操作。调用本接口后，对应操作可能被 TEE 异步中止。

**参数**：

  - <span class="reference">operation</span> 目标操作的 <span class="reference">TEEC\_Operation</span> 结构体指针。该结构必须是某个正在执行中的 <span class="reference">OpenSession</span> / <span class="reference">InvokeCommand</span> 使用的同一份对象。

**注意**：

  - 本接口是"请求"而非"强制"，能否真正中止由 TEE 和目标 TA 决定。
  - TA 需要在 GP Internal API 中调用 <span class="reference">TEE\_GetCancellationFlag</span> 配合才能响应取消请求。

> **权威参考**：  
> \- [GlobalPlatform TEE Internal Core API Specification v1.3.1](https://globalplatform.org/specs-library/tee-internal-core-api-specification/)
