# 线程 API

openvela 提供 POSIX 兼容的线程（pthread）接口，支持线程创建、同步、属性管理等功能。

头文件：<span class="reference">\#include \<pthread.h\></span>

# openvela 实现说明

openvela 的 pthread 实现基于 NuttX RTOS 内核，与标准 Linux 实现存在以下差异：

  - **<span class="reference">pthread\_t</span> 即 <span class="reference">pid\_t</span>**：在 openvela 中，线程 ID 的底层类型是 <span class="reference">pid\_t</span>（进程 ID），可以直接用于 <span class="reference">kill()</span> 等系统调用。
  - **无进程隔离**：openvela 不支持 Linux 意义上的进程，所有线程运行在同一地址空间。<span class="reference">PTHREAD\_PROCESS\_SHARED</span> 属性可设置但行为与 <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span> 相同。
  - **竞争范围固定**：仅支持 <span class="reference">PTHREAD\_SCOPE\_SYSTEM</span>，<span class="reference">PTHREAD\_SCOPE\_PROCESS</span> 返回 <span class="reference">ENOTSUP</span>。
  - **<span class="reference">fork()</span> 支持有限**：<span class="reference">pthread\_atfork()</span> 接口存在但 <span class="reference">fork()</span> 在 RTOS 环境中可能不可用，主要用于 POSIX 兼容性。
  - **条件编译依赖**：部分功能需要特定配置项：
  - <span class="reference">CONFIG\_SMP</span>：CPU 亲和性接口（<span class="reference">pthread\_setaffinity\_np</span> 等）
  - <span class="reference">CONFIG\_PRIORITY\_INHERITANCE</span>：优先级继承协议（<span class="reference">PTHREAD\_PRIO\_INHERIT</span>）
  - <span class="reference">CONFIG\_PRIORITY\_PROTECT</span>：优先级上限保护（<span class="reference">PTHREAD\_PRIO\_PROTECT</span>、<span class="reference">prioceiling</span> 相关接口）
  - <span class="reference">CONFIG\_RR\_INTERVAL \> 0</span>：<span class="reference">SCHED\_RR</span> 调度策略
  - <span class="reference">CONFIG\_SCHED\_SPORADIC</span>：<span class="reference">SCHED\_SPORADIC</span> 调度策略

# 线程创建与管理

## pthread\_create

    int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                       pthread_startroutine_t start_routine, pthread_addr_t arg);

> **类型说明**：<span class="reference">pthread\_startroutine\_t</span> 等价于 <span class="reference">void \*(\*)(void \*)</span>，<span class="reference">pthread\_addr\_t</span> 等价于 <span class="reference">void \*</span>，均为 NuttX 的类型别名。

创建一个新线程并使其可运行。新线程从 <span class="reference">start\_routine</span> 函数开始执行，该函数接收 <span class="reference">arg</span> 作为唯一参数。线程属性对象 <span class="reference">attr</span> 指定了新线程的各种属性，如栈大小、调度策略、优先级等。

如果 <span class="reference">attr</span> 为 <span class="reference">NULL</span>，则使用默认属性创建线程。默认情况下，线程是可连接的（joinable），具有默认的栈大小和调度策略。

**参数**：

  - <span class="reference">thread</span> 指向 <span class="reference">pthread\_t</span> 类型的指针，用于存储新创建线程的 ID。成功时，线程 ID 会被写入此位置。
  - <span class="reference">attr</span> 指向线程属性对象的指针。如果为 <span class="reference">NULL</span>，使用默认属性（栈大小为 <span class="reference">PTHREAD\_STACK\_DEFAULT</span>，调度策略为 <span class="reference">SCHED\_OTHER</span>，可连接状态）。
  - <span class="reference">start\_routine</span> 线程入口函数，函数签名为 <span class="reference">void \*(\*)(void \*)</span>。新线程将从此函数开始执行。
  - <span class="reference">arg</span> 传递给入口函数的参数。如果需要传递多个参数，可以传递结构体指针。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EAGAIN</span> 系统资源不足，无法创建新线程，或达到了系统线程数限制。
  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 中的设置无效。
  - <span class="reference">EPERM</span> 没有权限设置指定的调度策略或参数。

**注意**：

  - 新创建的线程与调用线程共享相同的地址空间、文件描述符和信号处理。
  - 如果线程创建时指定了 <span class="reference">PTHREAD\_CREATE\_DETACHED</span> 状态，线程终止后会自动释放资源，无需调用 <span class="reference">pthread\_join()</span>。
  - 线程创建后立即可调度运行，不保证创建顺序就是执行顺序。
  - 线程的返回值可以通过 <span class="reference">pthread\_join()</span> 获取，或通过 <span class="reference">pthread\_exit()</span> 显式返回。
  - 确保传递给线程的参数在线程执行期间保持有效，避免传递栈上的局部变量地址。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_exit

    void pthread_exit(void *exit_value);

终止调用线程并返回一个值，该值可被其他调用 <span class="reference">pthread\_join()</span> 等待此线程的线程获取。此函数不会返回到调用者。

调用 <span class="reference">pthread\_exit()</span> 等效于从线程入口函数返回，但可以在线程调用的任何函数中调用。线程终止时，会执行以下清理操作：

1.  调用通过 <span class="reference">pthread\_cleanup\_push()</span> 注册的清理函数（按注册顺序的逆序）。
2.  调用线程特定数据的析构函数（对于所有非 <span class="reference">NULL</span> 的线程特定数据键）。
3.  如果线程是可连接的，保留线程 ID 和返回值，直到其他线程调用 <span class="reference">pthread\_join()</span>。
4.  如果线程是分离的，立即释放所有资源。

**参数**：

  - <span class="reference">exit\_value</span> 线程返回值，这是一个无类型指针，可以传递任何数据的地址。等待此线程的 <span class="reference">pthread\_join()</span> 调用可以获取此值。如果线程被取消，返回值为 <span class="reference">PTHREAD\_CANCELED</span>。

**返回值**：

此函数不返回。调用后，调用线程终止。

**注意**：

  - 不要在 <span class="reference">main()</span> 函数中调用 <span class="reference">pthread\_exit()</span>，这会终止主线程但不终止进程，可能导致其他线程成为孤儿。
  - 如果线程已分离，<span class="reference">exit\_value</span> 将被忽略，因为没有线程可以通过 <span class="reference">pthread\_join()</span> 获取返回值。
  - 线程终止时，不会自动关闭打开的文件描述符或释放分配的内存，这些资源由整个进程共享。
  - 从线程入口函数返回隐式调用 <span class="reference">pthread\_exit()</span>，返回值作为线程的退出值。
  - 如果线程持有互斥锁，在调用 <span class="reference">pthread\_exit()</span> 前应释放，否则可能导致死锁。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_join

    int pthread_join(pthread_t thread, pthread_addr_t *value);

> **类型说明**：<span class="reference">pthread\_addr\_t</span> 等价于 <span class="reference">void \*</span>，为 NuttX 的类型别名。

阻塞调用线程，直到指定的线程 <span class="reference">thread</span> 终止。如果该线程已经终止，<span class="reference">pthread\_join()</span> 立即返回。成功返回后，目标线程被"连接"（joined），其资源被回收。

每个可连接的线程只能被连接一次。尝试连接已被连接或分离的线程会导致未定义行为。线程不能连接自己，否则会导致死锁。

**参数**：

  - <span class="reference">thread</span> 要等待的线程 ID，必须是可连接状态的线程。不能是分离状态的线程，也不能是已被连接过的线程。
  - <span class="reference">value</span> 指向指针的指针，用于接收线程的返回值。如果非 <span class="reference">NULL</span>，目标线程的返回值（通过 <span class="reference">pthread\_exit()</span> 或从入口函数返回）会被写入 <span class="reference">\*value</span>。如果线程被取消，<span class="reference">\*value</span> 设置为 <span class="reference">PTHREAD\_CANCELED</span>。如果不关心返回值，可以传递 <span class="reference">NULL</span>。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EDEADLK</span> 检测到死锁（如线程尝试连接自己），或 <span class="reference">thread</span> 指定另一个正在等待连接调用线程的线程。
  - <span class="reference">EINVAL</span> <span class="reference">thread</span> 不是可连接的线程，或者已有其他线程正在等待连接该线程。
  - <span class="reference">ESRCH</span> 找不到 ID 为 <span class="reference">thread</span> 的线程。

**注意**：

  - <span class="reference">pthread\_join()</span> 会阻塞调用线程，直到目标线程终止。如果目标线程已经终止，调用立即返回。
  - 连接线程后，线程 ID 被回收，不应再使用。
  - 如果多个线程同时尝试连接同一个线程，行为是未定义的。
  - 不连接可连接的线程会导致资源泄漏（类似于内存泄漏），线程资源不会被回收。
  - 对于不需要获取返回值的线程，建议在创建时设置为分离状态，或创建后调用 <span class="reference">pthread\_detach()</span>。
  - 在 openvela 中，线程 ID 实际上是进程 ID（<span class="reference">pid\_t</span>），可以用于其他系统调用。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_detach

    int pthread_detach(pthread_t thread);

将指定线程标记为分离状态。分离状态的线程在终止时会自动释放所有资源，无需其他线程调用 <span class="reference">pthread\_join()</span> 来回收。一旦线程被分离，就不能再被连接，线程的返回值也无法获取。

线程可以通过两种方式变为分离状态：  
1\. 创建时在属性对象中设置 <span class="reference">PTHREAD\_CREATE\_DETACHED</span>。  
2\. 创建后调用 <span class="reference">pthread\_detach()</span>。

线程也可以分离自己，通过 <span class="reference">pthread\_detach(pthread\_self())</span>。

**参数**：

  - <span class="reference">thread</span> 要分离的线程 ID。可以是其他线程的 ID，也可以是调用线程自己的 ID（通过 <span class="reference">pthread\_self()</span> 获取）。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">thread</span> 不是可连接的线程（可能已经是分离状态）。
  - <span class="reference">ESRCH</span> 找不到 ID 为 <span class="reference">thread</span> 的线程。

**注意**：

  - 分离线程后，不能再调用 <span class="reference">pthread\_join()</span> 等待该线程，否则会返回错误。
  - 分离状态是不可逆的，一旦分离就无法再变回可连接状态。
  - 对于不需要获取返回值或等待其完成的线程，应该设置为分离状态，以避免资源泄漏。
  - 分离状态不影响线程的执行，只影响线程终止后的资源回收方式。
  - 如果对已分离的线程再次调用 <span class="reference">pthread\_detach()</span>，会返回 <span class="reference">EINVAL</span> 错误。
  - 主线程可以是分离的，但这通常不是好的做法，因为主线程终止会导致整个进程终止。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_cancel

    int pthread_cancel(pthread_t thread);

向指定线程发送取消请求。线程是否响应取消请求取决于其取消状态（由 <span class="reference">pthread\_setcancelstate()</span> 设置）和取消类型（由 <span class="reference">pthread\_setcanceltype()</span> 设置）。

如果取消请求成功传递，目标线程的取消状态和类型决定了何时以及如何处理取消：

  - 如果取消状态为 <span class="reference">PTHREAD\_CANCEL\_DISABLE</span>，取消请求被挂起，直到取消状态变为 <span class="reference">PTHREAD\_CANCEL\_ENABLE</span>。
  - 如果取消状态为 <span class="reference">PTHREAD\_CANCEL\_ENABLE</span>，且取消类型为 <span class="reference">PTHREAD\_CANCEL\_DEFERRED</span>，取消在下一个取消点发生。
  - 如果取消类型为 <span class="reference">PTHREAD\_CANCEL\_ASYNCHRONOUS</span>，取消可能立即发生（但也可能延迟）。

**参数**：

  - <span class="reference">thread</span> 要取消的线程 ID。不能取消自己（应使用 <span class="reference">pthread\_exit()</span>）。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ESRCH</span> 找不到 ID 为 <span class="reference">thread</span> 的线程。

**注意**：

  - <span class="reference">pthread\_cancel()</span> 只是发送取消请求，不会等待线程实际终止。
  - 被取消的线程的退出值为 <span class="reference">PTHREAD\_CANCELED</span>。
  - 异步取消（<span class="reference">PTHREAD\_CANCEL\_ASYNCHRONOUS</span>）是危险的，应仅在特定情况下使用，因为线程可能在任意点被取消，可能导致资源泄漏或数据不一致。
  - 延迟取消（<span class="reference">PTHREAD\_CANCEL\_DEFERRED</span>，默认）更安全，线程只在取消点被取消，这些点包括 <span class="reference">pthread\_testcancel()</span>、<span class="reference">pthread\_join()</span>、<span class="reference">pthread\_cond\_wait()</span> 等阻塞调用。
  - 取消线程时，会执行清理处理程序（通过 <span class="reference">pthread\_cleanup\_push()</span> 注册）和线程特定数据析构函数。
  - 如果线程持有锁或其他资源，应通过清理处理程序确保资源被正确释放。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_setcancelstate

    int pthread_setcancelstate(int state, int *oldstate);

设置调用线程的取消状态。取消状态决定了线程是否可以被取消。

**参数**：

  - <span class="reference">state</span> 新的取消状态。有效值为：
  - <span class="reference">PTHREAD\_CANCEL\_ENABLE</span> 启用取消（默认）。线程可以响应取消请求。
  - <span class="reference">PTHREAD\_CANCEL\_DISABLE</span> 禁用取消。取消请求会被挂起，直到取消状态变为启用。
  - <span class="reference">oldstate</span> 如果非 <span class="reference">NULL</span>，用于存储之前的取消状态。可以传递 <span class="reference">NULL</span> 如果不需要获取旧值。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">state</span> 不是有效的取消状态值。

**注意**：

  - 新创建的线程默认取消状态为 <span class="reference">PTHREAD\_CANCEL\_ENABLE</span>。
  - 禁用取消不会丢弃挂起的取消请求，只是延迟其处理。
  - 即使禁用取消，线程仍可以通过 <span class="reference">pthread\_exit()</span> 自行终止。
  - 在执行关键代码段（如资源分配和初始化）时，应临时禁用取消，完成后再启用。
  - 取消状态是线程局部的，每个线程有自己独立的取消状态。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_setcanceltype

    int pthread_setcanceltype(int type, int *oldtype);

设置调用线程的取消类型。取消类型决定了线程如何响应取消请求。

**参数**：

  - <span class="reference">type</span> 新的取消类型。有效值为：
  - <span class="reference">PTHREAD\_CANCEL\_DEFERRED</span> 延迟取消（默认）。取消请求在下一个取消点才会处理。取消点包括 <span class="reference">pthread\_testcancel()</span>、<span class="reference">pthread\_join()</span>、<span class="reference">pthread\_cond\_wait()</span>、<span class="reference">pthread\_cond\_timedwait()</span>、<span class="reference">sem\_wait()</span> 等阻塞函数。
  - <span class="reference">PTHREAD\_CANCEL\_ASYNCHRONOUS</span> 异步取消。线程可以在任何时刻被取消（实际行为依赖于实现）。这种模式非常危险，应避免使用。
  - <span class="reference">oldtype</span> 如果非 <span class="reference">NULL</span>，用于存储之前的取消类型。可以传递 <span class="reference">NULL</span> 如果不需要获取旧值。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">type</span> 不是有效的取消类型值。

**注意**：

  - 新创建的线程默认取消类型为 <span class="reference">PTHREAD\_CANCEL\_DEFERRED</span>。
  - 延迟取消是推荐的取消类型，因为它只在定义明确的取消点响应取消，确保线程处于已知状态。
  - 异步取消可能在任意指令处中断线程，可能导致资源泄漏、数据损坏或未定义行为。只有确保线程代码是异步取消安全的，才应使用异步取消。
  - 如果使用异步取消，线程不应调用非异步取消安全的函数，包括大多数库函数。
  - 取消类型是线程局部的，每个线程有自己独立的取消类型。
  - 即使设置了异步取消，实现也可能将其视为延迟取消。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_testcancel

    void pthread_testcancel(void);

创建一个取消点。如果有挂起的取消请求且取消状态为启用，则线程将被取消并不返回。这是一种显式检查并响应取消请求的方式。

取消点是线程可以响应取消请求的位置。POSIX 定义了一些函数必须是取消点（如 <span class="reference">pthread\_join()</span>、<span class="reference">sem\_wait()</span> 等阻塞调用），而 <span class="reference">pthread\_testcancel()</span> 允许在任意位置创建取消点。

**参数**：

无参数。

**返回值**：

如果没有挂起的取消请求，函数正常返回。如果有挂起的取消请求，函数不返回，线程被取消。

**注意**：

  - 如果线程取消状态为 <span class="reference">PTHREAD\_CANCEL\_DISABLE</span>，<span class="reference">pthread\_testcancel()</span> 不起作用，直接返回。
  - 此函数通常用于长时间运行的计算密集型代码中，以提供响应取消请求的机会。
  - 应在适当的位置（如循环中）定期调用 <span class="reference">pthread\_testcancel()</span>，以确保线程能够及时响应取消请求。
  - 如果线程被取消，会执行清理处理程序和线程特定数据析构函数。
  - 过于频繁地调用 <span class="reference">pthread\_testcancel()</span> 可能影响性能；应在逻辑上合理的位置调用。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_self

    pthread_t pthread_self(void);

获取调用线程的线程 ID。线程 ID 在进程内唯一标识一个线程，可用于 <span class="reference">pthread\_join()</span>、<span class="reference">pthread\_detach()</span>、<span class="reference">pthread\_equal()</span> 等函数。

在 openvela 中，<span class="reference">pthread\_t</span> 实际上是 <span class="reference">pid\_t</span> 类型，即线程 ID 与进程 ID 相同。

**参数**：

无参数。

**返回值**：

返回调用线程的线程 ID。此函数总是成功，不会失败。

**注意**：

  - 线程 ID 在线程生命周期内保持不变。
  - 线程 ID 在线程终止并被连接后可能被重用。
  - 不要依赖线程 ID 的数值或顺序，它们是不透明的标识符。
  - 可以用 <span class="reference">pthread\_self()</span> 获取的 ID 调用 <span class="reference">pthread\_detach(pthread\_self())</span> 来分离当前线程。
  - 在 openvela 中，可以将线程 ID 用于系统调用，如信号发送等。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_equal

    int pthread_equal(pthread_t t1, pthread_t t2);

比较两个线程 ID 是否相等。由于线程 ID 的内部表示可能是复杂的数据结构，POSIX 要求使用此函数而不是直接用 <span class="reference">==</span> 比较。

**参数**：

  - <span class="reference">t1</span> 第一个线程 ID。
  - <span class="reference">t2</span> 第二个线程 ID。

**返回值**：

如果两个线程 ID 相等，返回非零值；否则返回 0。

**注意**：

  - 在 openvela 中，<span class="reference">pthread\_t</span> 是简单的整数类型（<span class="reference">pid\_t</span>），可以直接用 <span class="reference">==</span> 比较，但为了可移植性，建议使用 <span class="reference">pthread\_equal()</span>。
  - 终止的线程 ID 可能被重用，因此不应假设 ID 的唯一性跨越线程生命周期。
  - 常用于判断某个线程 ID 是否是当前线程：<span class="reference">pthread\_equal(thread\_id, pthread\_self())</span>。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_yield

    void pthread_yield(void);

主动让出处理器，允许其他线程运行。这是一个优化提示，实际行为取决于调度策略。

调用 <span class="reference">pthread\_yield()</span> 后，调用线程被放置在其优先级队列的末尾，调度器选择下一个可运行的线程。如果没有其他同等或更高优先级的就绪线程，调用线程可能立即继续执行。

**参数**：

无参数。

**返回值**：

无返回值。

**注意**：

  - 此函数是非标准的扩展接口，但在许多系统上可用（Linux、BSD 等）。
  - 在 POSIX 标准中，应使用 <span class="reference">sched\_yield()</span> 替代。
  - 适用于协作式多任务场景，线程主动让出 CPU 给其他线程。
  - 不应依赖 <span class="reference">pthread\_yield()</span> 来解决同步问题，应使用适当的同步原语（如互斥锁、条件变量）。
  - 过度使用 <span class="reference">pthread\_yield()</span> 可能导致性能下降，应仅在明确需要时使用。
  - 在实时系统中，<span class="reference">pthread\_yield()</span> 的行为取决于调度策略（FIFO、RR 等）。

**POSIX 兼容性**：兼容扩展接口（非 POSIX 标准，但广泛支持）。

## pthread\_once

    int pthread_once(pthread_once_t *once_control, void (*init_routine)(void));

确保初始化函数 <span class="reference">init\_routine</span> 在进程生命周期内只被调用一次，无论有多少线程调用 <span class="reference">pthread\_once()</span>。这是一种线程安全的单次初始化机制，常用于全局资源的延迟初始化。

<span class="reference">once\_control</span> 必须是静态或全局变量，并使用 <span class="reference">PTHREAD\_ONCE\_INIT</span> 初始化。多个线程可以同时调用 <span class="reference">pthread\_once()</span>，但 <span class="reference">init\_routine</span> 只会被执行一次，其他线程会阻塞等待直到初始化完成。

**参数**：

  - <span class="reference">once\_control</span> 控制变量，用于跟踪初始化状态。必须使用 <span class="reference">PTHREAD\_ONCE\_INIT</span> 初始化（如 <span class="reference">pthread\_once\_t once = PTHREAD\_ONCE\_INIT;</span>）。
  - <span class="reference">init\_routine</span> 初始化函数，无参数无返回值。此函数在整个进程生命周期内只会被调用一次。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">once\_control</span> 或 <span class="reference">init\_routine</span> 为 <span class="reference">NULL</span>。

**注意**：

  - <span class="reference">pthread\_once()</span> 是线程安全的，可以从多个线程同时调用。
  - 初始化函数应快速完成，避免阻塞其他等待初始化完成的线程。
  - 如果初始化函数内部调用 <span class="reference">pthread\_once()</span> 使用相同的 <span class="reference">once\_control</span>，行为是未定义的（可能死锁）。
  - 初始化函数不应调用 <span class="reference">pthread\_exit()</span> 或被取消，否则初始化被视为未完成，下次调用 <span class="reference">pthread\_once()</span> 会再次执行初始化。
  - 常用于单例模式、全局资源初始化等场景。
  - <span class="reference">once\_control</span> 变量不应被直接修改，只能通过 <span class="reference">pthread\_once()</span> 操作。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_atfork

    int pthread_atfork(void (*prepare)(void), void (*parent)(void), void (*child)(void));

注册在 <span class="reference">fork()</span> 调用时执行的处理函数。这些函数用于处理多线程环境中 <span class="reference">fork()</span> 带来的问题，特别是锁状态的一致性。

当调用 <span class="reference">fork()</span> 时，处理函数按以下顺序执行：  
1\. 在 <span class="reference">fork()</span> 之前，在父进程中调用所有 <span class="reference">prepare</span> 函数（按注册顺序的逆序）。  
2\. <span class="reference">fork()</span> 创建子进程。  
3\. 在子进程中调用所有 <span class="reference">child</span> 函数（按注册顺序）。  
4\. 在父进程中调用所有 <span class="reference">parent</span> 函数（按注册顺序）。

**参数**：

  - <span class="reference">prepare</span> 在 <span class="reference">fork()</span> 前在父进程中调用。通常用于获取所有锁，确保一致状态。可以为 <span class="reference">NULL</span>。
  - <span class="reference">parent</span> 在 <span class="reference">fork()</span> 后在父进程中调用。通常用于释放 <span class="reference">prepare</span> 中获取的锁。可以为 <span class="reference">NULL</span>。
  - <span class="reference">child</span> 在 <span class="reference">fork()</span> 后在子进程中调用。通常用于重新初始化锁状态和其他资源。可以为 <span class="reference">NULL</span>。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ENOMEM</span> 内存不足，无法分配记录处理函数所需的空间。

**注意**：

  - 可以多次调用 <span class="reference">pthread\_atfork()</span> 注册多组处理函数。
  - <span class="reference">prepare</span> 函数按注册顺序的逆序调用，<span class="reference">parent</span> 和 <span class="reference">child</span> 函数按注册顺序调用。
  - 在多线程程序中使用 <span class="reference">fork()</span> 是危险的，因为子进程只继承调用 <span class="reference">fork()</span> 的线程，其他线程在子进程中不存在，但它们持有的锁状态被继承，可能导致死锁。
  - <span class="reference">pthread\_atfork()</span> 处理函数应快速执行，避免调用可能阻塞或使用锁的复杂函数。
  - 在子进程中，只应调用异步信号安全的函数（如 <span class="reference">exec()</span> 系列函数）。
  - openvela 作为 RTOS，<span class="reference">fork()</span> 支持可能有限或不存在，此接口主要用于兼容性。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

# 线程属性

## pthread\_attr\_init

    int pthread_attr_init(pthread_attr_t *attr);

初始化线程属性对象为默认值。属性对象用于在创建线程时指定线程的各种属性，如栈大小、调度策略、优先级、分离状态等。

初始化后的属性对象包含以下默认值：  
\- 分离状态：<span class="reference">PTHREAD\_CREATE\_JOINABLE</span>（可连接）  
\- 栈大小：<span class="reference">PTHREAD\_STACK\_DEFAULT</span>（系统默认）  
\- 调度策略：<span class="reference">SCHED\_OTHER</span>（或系统默认策略）  
\- 调度继承：<span class="reference">PTHREAD\_INHERIT\_SCHED</span>（继承父线程）  
\- 作用域：<span class="reference">PTHREAD\_SCOPE\_SYSTEM</span>

**参数**：

  - <span class="reference">attr</span> 指向要初始化的线程属性对象。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ENOMEM</span> 内存不足，无法初始化属性对象。

**注意**：

  - 属性对象初始化后，可以通过各种 <span class="reference">pthread\_attr\_set\*()</span> 函数修改具体属性。
  - 同一个属性对象可以用于创建多个线程。
  - 使用完毕后，应调用 <span class="reference">pthread\_attr\_destroy()</span> 销毁属性对象，释放资源。
  - 属性对象的修改不影响已创建的线程，只影响后续使用该属性对象创建的线程。
  - 在 openvela 中，属性对象是简单的结构体，不涉及动态内存分配。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_attr\_destroy

    int pthread_attr_destroy(pthread_attr_t *attr);

销毁线程属性对象，释放其占用的资源。销毁后的属性对象不能再使用，除非重新初始化。

**参数**：

  - <span class="reference">attr</span> 指向要销毁的属性对象。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 不是有效的属性对象。

**注意**：

  - 销毁属性对象不影响已使用该对象创建的线程。
  - 销毁后的属性对象可以通过 <span class="reference">pthread\_attr\_init()</span> 重新初始化并使用。
  - 在 openvela 中，属性对象通常不涉及动态内存，此函数主要用于 POSIX 兼容性。
  - 应始终配对调用 <span class="reference">pthread\_attr\_init()</span> 和 <span class="reference">pthread\_attr\_destroy()</span>，遵循资源管理的最佳实践。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

# 互斥锁

## pthread\_mutex\_init

    int pthread_mutex_init(pthread_mutex_t *mutex, const pthread_mutexattr_t *attr);

初始化互斥锁。互斥锁用于保护共享资源，确保同一时刻只有一个线程可以访问被保护的临界区。

如果 <span class="reference">attr</span> 为 <span class="reference">NULL</span>，使用默认属性：类型为 <span class="reference">PTHREAD\_MUTEX\_NORMAL</span>，不支持优先级继承或保护协议，进程私有。

互斥锁也可以使用 <span class="reference">PTHREAD\_MUTEX\_INITIALIZER</span> 静态初始化：  

    pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

**参数**：

  - <span class="reference">mutex</span> 指向要初始化的互斥锁对象。
  - <span class="reference">attr</span> 指向互斥锁属性对象。如果为 <span class="reference">NULL</span>，使用默认属性。属性包括互斥锁类型（normal、recursive、errorcheck）、优先级协议、健壮性等。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EAGAIN</span> 系统资源不足，无法初始化互斥锁。
  - <span class="reference">ENOMEM</span> 内存不足。
  - <span class="reference">EPERM</span> 调用者没有权限。
  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 中的属性值无效。

**注意**：

  - 初始化后的互斥锁处于未锁定状态。
  - 不要重复初始化已初始化的互斥锁，这会导致未定义行为。
  - 使用完毕后应调用 <span class="reference">pthread\_mutex\_destroy()</span> 销毁互斥锁。
  - 静态初始化的互斥锁不需要显式销毁。
  - 互斥锁类型影响重复加锁和错误检测行为：
  - <span class="reference">PTHREAD\_MUTEX\_NORMAL</span>：不检测死锁，重复加锁会导致死锁。
  - <span class="reference">PTHREAD\_MUTEX\_ERRORCHECK</span>：检测死锁和错误，性能略低。
  - <span class="reference">PTHREAD\_MUTEX\_RECURSIVE</span>：允许同一线程多次加锁，需要相同次数的解锁。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_destroy

    int pthread_mutex_destroy(pthread_mutex_t *mutex);

销毁互斥锁，释放其占用的资源。

**参数**：

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">mutex</span> 为 <span class="reference">NULL</span> 或未正确初始化。
  - <span class="reference">EBUSY</span> 互斥锁当前被锁定，无法销毁。

**注意**：

  - 不能销毁正在被使用（锁定）的互斥锁。
  - 销毁后的互斥锁不能再使用，除非重新初始化。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_lock

    int pthread_mutex_lock(pthread_mutex_t *mutex);

锁定互斥锁。如果互斥锁当前未被锁定，调用线程获得锁并立即返回。如果互斥锁已被其他线程锁定，调用线程阻塞等待，直到锁可用。

具体行为取决于互斥锁类型：  
\- **NORMAL（默认）**：如果锁已被当前线程持有，再次加锁会导致死锁。  
\- **ERRORCHECK**：如果锁已被当前线程持有，返回 <span class="reference">EDEADLK</span> 错误。  
\- **RECURSIVE**：如果锁已被当前线程持有，递增锁计数，需要相同次数的解锁。

**参数**：

  - <span class="reference">mutex</span> 指向要锁定的互斥锁。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EDEADLK</span> 互斥锁类型为 <span class="reference">PTHREAD\_MUTEX\_ERRORCHECK</span>，且当前线程已持有该锁（死锁检测）。
  - <span class="reference">EINVAL</span> 互斥锁未正确初始化。
  - <span class="reference">EOWNERDEAD</span> 互斥锁是健壮互斥锁，前一个持有者终止时未释放锁。调用者现在拥有该锁，应调用 <span class="reference">pthread\_mutex\_consistent()</span> 使其一致，或解锁并不再使用。
  - <span class="reference">ENOTRECOVERABLE</span> 健壮互斥锁处于不可恢复状态，无法再使用。

**注意**：

  - 持有锁的线程应尽快释放锁，避免其他线程长时间等待。
  - 避免在持有锁时调用可能阻塞的函数（如 I/O 操作），这可能导致性能问题。
  - 避免嵌套锁定多个互斥锁，这可能导致死锁。如果必须，应保持固定的加锁顺序。
  - 锁定互斥锁后，应使用 <span class="reference">try-finally</span> 模式或清理处理程序确保锁始终被释放。
  - 如果线程被取消，应通过清理处理程序（<span class="reference">pthread\_cleanup\_push/pop</span>）确保锁被释放。
  - 优先级反转问题：如果启用优先级继承协议，低优先级线程持有锁时，其优先级临时提升到等待线程的最高优先级。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_trylock

    int pthread_mutex_trylock(pthread_mutex_t *mutex);

尝试锁定互斥锁（非阻塞）。如果互斥锁当前可用，函数获得锁并立即返回成功。如果互斥锁已被锁定，函数立即返回 <span class="reference">EBUSY</span>，不会阻塞等待。

这是 <span class="reference">pthread\_mutex\_lock()</span> 的非阻塞版本，适用于不希望等待锁的场景，如轮询、避免死锁等。

**参数**：

  - <span class="reference">mutex</span> 指向要尝试锁定的互斥锁。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EBUSY</span> 互斥锁已被锁定，无法获取。这不是真正的错误，只是表示锁当前不可用。
  - <span class="reference">EINVAL</span> 互斥锁未正确初始化。
  - <span class="reference">EDEADLK</span> 互斥锁类型为 <span class="reference">PTHREAD\_MUTEX\_ERRORCHECK</span>，且当前线程已持有该锁。
  - <span class="reference">EOWNERDEAD</span> 健壮互斥锁的前一个持有者终止时未释放锁。
  - <span class="reference">ENOTRECOVERABLE</span> 健壮互斥锁处于不可恢复状态。

**注意**：

  - 如果返回 <span class="reference">EBUSY</span>，调用者可以选择稍后重试或执行其他操作。
  - 对于递归互斥锁，如果当前线程已持有锁，<span class="reference">pthread\_mutex\_trylock()</span> 会成功并递增锁计数。
  - 常用于避免死锁的场景：尝试获取多个锁时，如果无法获取某个锁，可以释放已持有的锁并重试。
  - 不应在循环中持续调用 <span class="reference">pthread\_mutex\_trylock()</span>（忙等待），这会浪费 CPU 资源。
  - 适用于实现非阻塞算法或超时机制。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_timedlock

    int pthread_mutex_timedlock(pthread_mutex_t *mutex, const struct timespec *abstime);

带超时的锁定互斥锁。如果互斥锁不能立即获取，阻塞等待直到锁可用或超时。

**参数**：

  - <span class="reference">mutex</span> 指向要锁定的互斥锁。不能为 <span class="reference">NULL</span>。
  - <span class="reference">abstime</span> 绝对超时时间（基于 <span class="reference">CLOCK\_REALTIME</span>）。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ETIMEDOUT</span> 在超时时间内未能获取锁。
  - <span class="reference">EINVAL</span> <span class="reference">mutex</span> 为 <span class="reference">NULL</span> 或未正确初始化。
  - <span class="reference">EDEADLK</span> 互斥锁类型为 <span class="reference">PTHREAD\_MUTEX\_ERRORCHECK</span>，且当前线程已持有该锁。

**注意**：

  - 对于递归互斥锁，如果当前线程已持有锁，会成功并递增锁计数，不受超时影响。
  - 超时时间是绝对时间，不是相对时间。应基于 <span class="reference">clock\_gettime(CLOCK\_REALTIME, ...)</span> 计算。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_unlock

    int pthread_mutex_unlock(pthread_mutex_t *mutex);

解锁互斥锁，使其可供其他等待的线程获取。只有持有锁的线程才能解锁，否则行为取决于互斥锁类型。

对于递归互斥锁，每次 <span class="reference">pthread\_mutex\_unlock()</span> 调用递减锁计数，当计数降到零时锁才真正被释放。

**参数**：

  - <span class="reference">mutex</span> 指向要解锁的互斥锁。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EPERM</span> 当前线程不拥有该互斥锁。对于 <span class="reference">PTHREAD\_MUTEX\_ERRORCHECK</span> 类型，尝试解锁未持有的锁会返回此错误。对于 <span class="reference">PTHREAD\_MUTEX\_NORMAL</span> 类型，这是未定义行为。
  - <span class="reference">EINVAL</span> 互斥锁未正确初始化或已被销毁。

**注意**：

  - 必须由锁定互斥锁的同一线程解锁，不能由其他线程代为解锁。
  - 解锁未锁定的互斥锁是未定义行为（对于 NORMAL 类型）或返回错误（对于 ERRORCHECK 类型）。
  - 解锁互斥锁后，如果有线程正在等待该锁，其中一个等待线程会被唤醒并获得锁。具体哪个线程被唤醒取决于调度策略。
  - 在持有锁期间发生异常或取消时，应确保锁被释放，通过清理处理程序或异常处理机制。
  - 解锁操作应尽可能快，避免在锁保护的临界区外调用 unlock。
  - 对于优先级继承互斥锁，解锁时会恢复线程的原始优先级。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_consistent

    int pthread_mutex_consistent(pthread_mutex_t *mutex);

将健壮互斥锁标记为一致状态。当健壮互斥锁的前一个持有者终止时未释放锁，<span class="reference">pthread\_mutex\_lock()</span> 会返回 <span class="reference">EOWNERDEAD</span>，此时新的持有者应调用此函数使互斥锁恢复一致。

**参数**：

  - <span class="reference">mutex</span> 指向处于不一致状态的健壮互斥锁。不能为 <span class="reference">NULL</span>。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">mutex</span> 为 <span class="reference">NULL</span>，或互斥锁不是健壮互斥锁，或不处于不一致状态。

**注意**：

  - 需要互斥锁属性中设置了 <span class="reference">PTHREAD\_MUTEX\_ROBUST</span>。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_mutex\_setprioceiling

## pthread\_cond\_wait

    int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);

等待条件变量被通知。此函数原子性地释放互斥锁并阻塞在条件变量上。当条件变量被 <span class="reference">pthread\_cond\_signal()</span> 或 <span class="reference">pthread\_cond\_broadcast()</span> 通知时，线程被唤醒，重新获取互斥锁，然后返回。

条件变量通常用于实现生产者-消费者模式或其他需要线程间协调的场景。典型用法：  

    pthread_mutex_lock(&mutex);
    while (!condition) {
        pthread_cond_wait(&cond, &mutex);
    }
    // 条件满足，处理数据
    pthread_mutex_unlock(&mutex);

**参数**：

  - <span class="reference">cond</span> 指向条件变量。
  - <span class="reference">mutex</span> 指向关联的互斥锁。调用前必须已被当前线程锁定。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">cond</span> 或 <span class="reference">mutex</span> 未正确初始化，或使用了不同的互斥锁。
  - <span class="reference">EPERM</span> 调用线程未持有互斥锁。

**注意**：

  - 调用前必须持有关联的互斥锁，否则行为未定义。
  - 函数返回时，互斥锁已重新被锁定，即使发生错误。
  - 由于虚假唤醒的可能性，必须在循环中检查条件：<span class="reference">while (\!condition) pthread\_cond\_wait(...)</span>。虚假唤醒是指线程在没有信号通知的情况下被唤醒。
  - 条件变量本身不保存状态，它只是一个同步原语。实际条件（布尔表达式）由应用程序维护，通常通过共享变量表示。
  - 等待时互斥锁被原子性地释放，避免了释放锁和阻塞之间的竞态条件。
  - 如果线程被取消，互斥锁会被重新锁定，然后清理处理程序被调用。应在清理处理程序中释放锁。
  - 多个线程可以同时等待同一个条件变量。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_cond\_timedwait

    int pthread_cond_timedwait(pthread_cond_t *cond, pthread_mutex_t *mutex,
                               const struct timespec *abstime);

带超时的等待条件变量。行为与 <span class="reference">pthread\_cond\_wait()</span> 相同，但在超时后自动返回。

**参数**：

  - <span class="reference">cond</span> 指向条件变量。
  - <span class="reference">mutex</span> 指向关联的互斥锁，调用前必须已锁定。
  - <span class="reference">abstime</span> 绝对超时时间。时钟源取决于条件变量属性中的时钟设置（默认 <span class="reference">CLOCK\_REALTIME</span>）。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ETIMEDOUT</span> 在超时时间内未收到通知。
  - <span class="reference">EINVAL</span> 参数无效。

**注意**：

  - 即使超时返回，互斥锁也会被重新锁定。
  - 仍需在循环中检查条件，因为可能存在虚假唤醒。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_cond\_clockwait

    int pthread_cond_clockwait(pthread_cond_t *cond, pthread_mutex_t *mutex,
                               clockid_t clockid, const struct timespec *abstime);

使用指定时钟等待条件变量。允许在等待时直接指定时钟源，而不依赖属性对象中的设置。

**参数**：

  - <span class="reference">cond</span> 指向条件变量。
  - <span class="reference">mutex</span> 指向关联的互斥锁，调用前必须已锁定。
  - <span class="reference">clockid</span> 时钟 ID，如 <span class="reference">CLOCK\_REALTIME</span> 或 <span class="reference">CLOCK\_MONOTONIC</span>。
  - <span class="reference">abstime</span> 基于指定时钟的绝对超时时间。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">ETIMEDOUT</span> 在超时时间内未收到通知。
  - <span class="reference">EINVAL</span> 参数无效。

**POSIX 兼容性**：兼容扩展接口。

## pthread\_cond\_signal

    int pthread_cond_signal(pthread_cond_t *cond);

唤醒至少一个正在等待条件变量的线程。如果有多个线程在等待，调度策略决定哪个线程被唤醒。如果没有线程在等待，此调用不起作用（信号丢失）。

与 <span class="reference">pthread\_cond\_broadcast()</span> 不同，<span class="reference">pthread\_cond\_signal()</span> 只唤醒一个线程，适用于只有一个线程能够处理条件的场景，可以避免不必要的线程唤醒和上下文切换。

**参数**：

  - <span class="reference">cond</span> 指向要通知的条件变量。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">cond</span> 未正确初始化。

**注意**：

  - 调用 <span class="reference">pthread\_cond\_signal()</span> 时不需要持有关联的互斥锁，但通常建议在持有锁时调用，以避免竞态条件。

  - 被唤醒的线程不会立即执行，它会先尝试重新获取互斥锁。因此在调用 signal 后立即释放锁是一个好的做法。

  - 如果在修改条件后不持有锁就调用 signal，可能导致"唤醒丢失"问题：等待线程可能在检查条件和调用 wait 之间被抢占。

  - 典型模式：  
    
        pthread_mutex_lock(&mutex);
        // 修改共享状态，使条件成立
        condition = true;
        pthread_cond_signal(&cond);
        pthread_mutex_unlock(&mutex);

  - 如果条件可能满足多个等待线程的需求，应使用 <span class="reference">pthread\_cond\_broadcast()</span>。

  - POSIX 不保证信号的公平性，可能出现线程饥饿。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_cond\_broadcast

    int pthread_cond_broadcast(pthread_cond_t *cond);

唤醒所有正在等待条件变量的线程。所有等待线程被唤醒后，会竞争重新获取关联的互斥锁。如果没有线程在等待，此调用不起作用。

与 <span class="reference">pthread\_cond\_signal()</span> 不同，broadcast 唤醒所有等待线程，适用于条件变化可能影响多个线程的场景，或者不确定哪个线程应该被唤醒时。

**参数**：

  - <span class="reference">cond</span> 指向要广播的条件变量。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">cond</span> 未正确初始化。

**注意**：

  - 类似 <span class="reference">pthread\_cond\_signal()</span>，调用时通常应持有关联的互斥锁。

  - 所有被唤醒的线程会串行竞争互斥锁，一次只有一个线程能获得锁并继续执行。

  - 使用 broadcast 可能导致"惊群效应"（thundering herd）：多个线程被唤醒但只有少数能真正处理条件，其他线程发现条件不满足后又回到等待状态，造成不必要的上下文切换。

  - 适用场景：

  - 条件变化影响所有等待线程（如资源状态变化、系统关闭信号）

  - 不确定哪个线程应该处理条件

  - 需要所有线程重新评估其等待条件

  - 典型模式：  
    
        pthread_mutex_lock(&mutex);
        // 修改影响所有等待线程的共享状态
        shutdown = true;
        pthread_cond_broadcast(&cond);
        pthread_mutex_unlock(&mutex);

  - 如果只需要唤醒一个线程，优先使用 <span class="reference">pthread\_cond\_signal()</span> 以提高效率。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

# 条件变量属性

## pthread\_condattr\_init

    int pthread_condattr_init(pthread_condattr_t *attr);

初始化条件变量属性对象为默认值。初始化后的属性对象包含以下默认值：

  - 进程共享属性：<span class="reference">PTHREAD\_PROCESS\_PRIVATE</span>（进程私有）
  - 时钟属性：<span class="reference">CLOCK\_REALTIME</span>（系统实时时钟）

属性对象用于在调用 <span class="reference">pthread\_cond\_init()</span> 时指定条件变量的行为特性。同一个属性对象可以用于初始化多个条件变量。

**参数**：

  - <span class="reference">attr</span> 指向要初始化的条件变量属性对象。不能为 <span class="reference">NULL</span>。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 为 <span class="reference">NULL</span>。

**注意**：

  - 使用完毕后应调用 <span class="reference">pthread\_condattr\_destroy()</span> 销毁属性对象。
  - 属性对象的修改不影响已使用该对象创建的条件变量。
  - 如果需要使用 <span class="reference">CLOCK\_MONOTONIC</span> 作为超时时钟（避免系统时间调整的影响），应在初始化后调用 <span class="reference">pthread\_condattr\_setclock()</span> 修改时钟属性。
  - 在 openvela 中，属性对象是简单的结构体（包含 <span class="reference">pshared</span> 和 <span class="reference">clockid</span> 两个字段），不涉及动态内存分配。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_condattr\_destroy

    int pthread_condattr_destroy(pthread_condattr_t *attr);

销毁条件变量属性对象，释放其占用的资源。销毁后的属性对象不能再使用，除非重新调用 <span class="reference">pthread\_condattr\_init()</span> 初始化。

**参数**：

  - <span class="reference">attr</span> 指向要销毁的条件变量属性对象。不能为 <span class="reference">NULL</span>。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 为 <span class="reference">NULL</span> 或不是有效的属性对象。

**注意**：

  - 销毁属性对象不影响已使用该对象创建的条件变量。
  - 在 openvela 中，属性对象不涉及动态内存分配，此函数主要用于 POSIX 兼容性。
  - 应始终配对调用 <span class="reference">pthread\_condattr\_init()</span> 和 <span class="reference">pthread\_condattr\_destroy()</span>。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_condattr\_getpshared

    int pthread_condattr_getpshared(const pthread_condattr_t *attr, int *pshared);

获取条件变量属性对象中的进程共享属性。进程共享属性决定了条件变量是否可以被多个进程中的线程访问。

**参数**：

  - <span class="reference">attr</span> 指向条件变量属性对象。不能为 <span class="reference">NULL</span>。
  - <span class="reference">pshared</span> 指向整型变量的指针，用于存储当前的进程共享属性值。不能为 <span class="reference">NULL</span>。返回值为以下之一：
  - <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span> 条件变量只能被同一进程内的线程使用（默认值）。
  - <span class="reference">PTHREAD\_PROCESS\_SHARED</span> 条件变量可以被多个进程中的线程使用，前提是条件变量分配在共享内存中。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 或 <span class="reference">pshared</span> 为 <span class="reference">NULL</span>。

**注意**：

  - 在 openvela 中，由于 RTOS 的内存模型，<span class="reference">PTHREAD\_PROCESS\_SHARED</span> 的行为可能与 Linux 等系统不同。
  - 默认值为 <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span>。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_condattr\_setpshared

    int pthread_condattr_setpshared(pthread_condattr_t *attr, int pshared);

设置条件变量属性对象中的进程共享属性。该属性决定条件变量是否可以被不同进程中的线程操作。

如果设置为 <span class="reference">PTHREAD\_PROCESS\_SHARED</span>，任何能够访问条件变量所在内存的线程都可以操作该条件变量。如果设置为 <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span>，只有与初始化条件变量的线程在同一进程内的线程才能操作。不同进程的线程尝试操作私有条件变量的行为是未定义的。

**参数**：

  - <span class="reference">attr</span> 指向条件变量属性对象。不能为 <span class="reference">NULL</span>。
  - <span class="reference">pshared</span> 进程共享属性值，必须为以下之一：
  - <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span> 进程私有（默认）。
  - <span class="reference">PTHREAD\_PROCESS\_SHARED</span> 进程间共享。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 为 <span class="reference">NULL</span>，或 <span class="reference">pshared</span> 不是 <span class="reference">PTHREAD\_PROCESS\_SHARED</span> 或 <span class="reference">PTHREAD\_PROCESS\_PRIVATE</span>。

**注意**：

  - 使用 <span class="reference">PTHREAD\_PROCESS\_SHARED</span> 时，条件变量必须分配在所有相关进程都能访问的共享内存区域中。
  - 与条件变量关联的互斥锁也应设置为进程共享。
  - 修改属性对象不影响已创建的条件变量。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_condattr\_getclock

    int pthread_condattr_getclock(const pthread_condattr_t *attr, clockid_t *clock_id);

获取条件变量属性对象中的时钟属性。时钟属性决定了 <span class="reference">pthread\_cond\_timedwait()</span> 使用哪个时钟来计算超时时间。

**参数**：

  - <span class="reference">attr</span> 指向条件变量属性对象。不能为 <span class="reference">NULL</span>。
  - <span class="reference">clock\_id</span> 指向 <span class="reference">clockid\_t</span> 变量的指针，用于存储当前的时钟属性值。返回值为以下之一：
  - <span class="reference">CLOCK\_REALTIME</span> 系统实时时钟（默认值）。受系统时间调整（如 NTP）影响。
  - <span class="reference">CLOCK\_MONOTONIC</span> 单调递增时钟。不受系统时间调整影响。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 为 <span class="reference">NULL</span>。

**注意**：

  - 默认时钟为 <span class="reference">CLOCK\_REALTIME</span>。
  - 如果应用程序对超时精度有要求，或系统时间可能被调整，建议使用 <span class="reference">CLOCK\_MONOTONIC</span>。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_condattr\_setclock

    int pthread_condattr_setclock(pthread_condattr_t *attr, clockid_t clock_id);

设置条件变量属性对象中的时钟属性。该属性指定 <span class="reference">pthread\_cond\_timedwait()</span> 用于计算超时的时钟源。

选择合适的时钟对于超时行为至关重要：  
\- <span class="reference">CLOCK\_REALTIME</span>：使用系统实时时钟，超时时间是绝对时间点。如果系统时间被向前调整，可能导致提前超时；向后调整则可能导致超时延迟。  
\- <span class="reference">CLOCK\_MONOTONIC</span>：使用单调递增时钟，不受系统时间调整影响，适合需要精确超时控制的场景。

**参数**：

  - <span class="reference">attr</span> 指向条件变量属性对象。不能为 <span class="reference">NULL</span>。
  - <span class="reference">clock\_id</span> 时钟 ID，必须为以下之一：
  - <span class="reference">CLOCK\_REALTIME</span> 系统实时时钟（默认）。
  - <span class="reference">CLOCK\_MONOTONIC</span> 单调递增时钟。

**返回值**：

成功时返回 0，失败时返回错误码：

  - <span class="reference">EINVAL</span> <span class="reference">attr</span> 为 <span class="reference">NULL</span>，或 <span class="reference">clock\_id</span> 不是 <span class="reference">CLOCK\_REALTIME</span> 或 <span class="reference">CLOCK\_MONOTONIC</span>。

**注意**：

  - 在 openvela 中，仅支持 <span class="reference">CLOCK\_REALTIME</span> 和 <span class="reference">CLOCK\_MONOTONIC</span> 两种时钟，传入其他时钟 ID（如 <span class="reference">CLOCK\_PROCESS\_CPUTIME\_ID</span>）会返回 <span class="reference">EINVAL</span>。
  - 修改时钟属性不影响已创建的条件变量，仅影响后续使用该属性对象创建的条件变量。
  - 如果使用 <span class="reference">CLOCK\_MONOTONIC</span>，传递给 <span class="reference">pthread\_cond\_timedwait()</span> 的 <span class="reference">abstime</span> 应基于 <span class="reference">clock\_gettime(CLOCK\_MONOTONIC, ...)</span> 获取的时间计算。
  - 也可以使用 <span class="reference">pthread\_cond\_clockwait()</span> 在等待时直接指定时钟，而不依赖属性对象中的设置。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_rwlock\_wrlock

    int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);

获取写锁。写锁是排他的，必须等待所有读锁和写锁释放后才能获取。

# 屏障

## pthread\_barrier\_init

    int pthread_barrier_init(pthread_barrier_t *barrier,

## pthread\_barrier\_wait

    int pthread_barrier_wait(pthread_barrier_t *barrier);

在屏障处等待。当所有线程（数量由 <span class="reference">pthread\_barrier\_init</span> 的 <span class="reference">count</span> 参数指定）都调用此函数后，所有线程同时被释放继续执行。

初始化自旋锁。自旋锁使用忙等待方式获取锁，适用于锁持有时间极短的场景。

## pthread\_spin\_lock

# 线程清理

## pthread\_cleanup\_push

    void pthread_cleanup_push(void (*routine)(void *), void *arg);

注册线程清理函数。清理函数在线程被取消、调用 <span class="reference">pthread\_exit()</span> 或调用 <span class="reference">pthread\_cleanup\_pop(1)</span> 时执行。

**参数**：

  - <span class="reference">routine</span> 清理函数。不能为 <span class="reference">NULL</span>。
  - <span class="reference">arg</span> 传递给清理函数的参数。

**返回值**：

无返回值。

**注意**：

  - 必须与 <span class="reference">pthread\_cleanup\_pop()</span> 配对使用，且在同一函数作用域内。
  - 清理函数按注册顺序的逆序执行（后注册先执行）。
  - 常用于确保互斥锁在线程取消时被释放。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。

## pthread\_cleanup\_pop

    void pthread_cleanup_pop(int execute);

移除最近注册的清理函数，并可选择执行它。

**参数**：

  - <span class="reference">execute</span> 如果非零，移除并执行清理函数；如果为零，仅移除不执行。

**返回值**：

无返回值。

**注意**：

  - 必须与 <span class="reference">pthread\_cleanup\_push()</span> 配对使用。
  - 即使 <span class="reference">execute</span> 为 0，清理函数也会从栈中移除。

**POSIX 兼容性**：兼容 <span class="reference">POSIX</span> 同名接口。
