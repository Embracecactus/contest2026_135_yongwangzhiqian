# 一、GPIO 南向接口 (驱动层)

南向接口负责将底层的芯片（Chip）或板级（Board）GPIO 功能接入 openvela 的虚拟文件系统（VFS）或其他驱动子系统。开发者需要实现一套标准的操作函数集，以供北向接口调用。

openvela 提供两种实现南向接口的方式：

  - **<span class="reference">ioexpander</span>** **框架**：一种通用的 I/O 抽象框架，推荐用于管理大量或复用的 I/O 资源。
  - **<span class="reference">lower\_half</span>** **方式**：一种直接、轻量级的实现，通常与特定板级代码紧密绑定。

> **推荐**：在进行 SOC (System on a Chip) 适配时，我们推荐使用 <span class="reference">ioexpander</span> 方式。它能统一管理所有 I/O 资源，并能有效减少适配代码量。

## 1、<span class="reference">ioexpander</span> 框架

<span class="reference">ioexpander</span> 是一个通用的 I/O 扩展驱动框架，适用于需要统一管理大量 GPIO 的场景。采用此方式，您需要为 <span class="reference">ioexpander</span> 框架实现一套标准的回调函数。

<span class="reference">ioexpander</span> 驱动实例不仅可以在内核中被其他驱动直接高效调用，可以直接访问不同的引脚，甚至于同时访问多个引脚，还可以通过 <span class="reference">gpio\_lower\_half()</span> 接口将每个引脚注册为用户空间可见的 <span class="reference">/dev/gpiox</span> 设备。

内核通过 [drivers/ioexpander/gpio\_lower\_half.c](https://github.com/apache/nuttx/blob/master/drivers/ioexpander/gpio_lower_half.c) 文件中的代码实现 <span class="reference">ioexpander</span> 与 VFS 之间的桥接，该桥接层会调用您在驱动中实现的 <span class="reference">IOEXP\_xxx</span> 宏接口，而宏接口也就需要按 <span class="reference">ioexpender</span> 所需要实现的接口分别实现。

![](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005743386_003.png)

### 配置选项

要使用 <span class="reference">ioexpander</span> 方式，请在配置中启用以下选项：  

    # 启用 ioexpander 框架
    CONFIG_IOEXPANDER=y
    # 启用将 ioexpander 桥接到 GPIO 字符设备的功能
    CONFIG_GPIO_LOWER_HALF=y
    # 用于支持多引脚批量操作
    CONFIG_IOEXPANDER_MULTIPIN=y
    # 用于支持中断功能
    CONFIG_IOEXPANDER_INT_ENABLE=y

### 依赖头文件

在 <span class="reference">ioexpander</span> 方式下，需要实现的接口定义在如下头文件中，在编写 GPIO 驱动时需要包含该头文件：  

    //配置依赖：CONFIG_GPIO_LOWER_HALF=y
    #include <nuttx/ioexpander/ioexpander.h>

### 核心接口实现

您需要实现 <span class="reference">ioexpander\_ops\_s</span> 结构体中定义的回调函数。下表总结了这些核心接口。

| **函数原型**                                                                                                                                                           | **描述**                                  | **状态**                                                              |
| :----------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------- | :------------------------------------------------------------------ |
| <span class="reference">int ioe\_direction(dev, pin, dir)</span>                                                                                                   | 设置单个引脚的方向（输入/输出/上拉/下拉等）。                | **必需**                                                              |
| <span class="reference">int ioe\_option(dev, pin, opt, val)</span>                                                                                                 | 配置引脚选项，如中断触发方式（边沿/电平）或有效电平。             | **必需**                                                              |
| <span class="reference">int ioe\_writepin(dev, pin, val)</span>/<span class="reference">int ioe\_readpin(dev, pin, \*val)</span>                                   | 对某个引脚进行读写操作。                            | **必需**                                                              |
| <span class="reference">int ioe\_readbuf(dev, pin, \*val)</span>                                                                                                   | 从内部缓冲区读取引脚电平。此操作效率高，但可能与引脚实际状态不一致。      | **必需**                                                              |
| <span class="reference">int ioe\_multiwritepin(dev, \*pins, \*vals, count)</span>/<span class="reference">int ioe\_multireadpin(dev, \*pins, \*vals, count)</span> | 批量读写多个引脚的电平值。                           | 可选 (<span class="reference">CONFIG\_IOEXPANDER\_MULTIPIN</span>)    |
| <span class="reference">int ioe\_multireadbuf(dev, \*pins, \*vals, count)</span>                                                                                   | 从内部缓冲区批量读取多个引脚的电平。此操作效率高，但可能与引脚实际状态不一致。 | 可选 (<span class="reference">CONFIG\_IOEXPANDER\_MULTIPIN</span>)    |
| <span class="reference">void \*ioe\_attach(dev, pinset, cb, arg)</span>                                                                                            | 附加一个中断回调函数到指定的引脚集。                      | 可选 (<span class="reference">CONFIG\_IOEXPANDER\_INT\_ENABLE</span>) |
| <span class="reference">int ioe\_detach(dev, handle)</span>                                                                                                        | 移除一个已附加的中断回调。                           | 可选 (<span class="reference">CONFIG\_IOEXPANDER\_INT\_ENABLE</span>) |

### 注意事项

1.  您需要在驱动初始化时，手动调用 <span class="reference">gpio\_lower\_half()</span> 函数，才能将 <span class="reference">ioexpander</span> 的引脚注册为用户空间可见的 <span class="reference">/dev/gpiox</span> 设备。
2.  设备注册名遵循固定规则 <span class="reference">/dev/gpiox</span>，其中 <span class="reference">x</span> 是引脚编号。

### 示例代码

  - **<span class="reference">ioexpander</span>** **驱动实现**：可参考 PCA9555 I/O 扩展芯片的驱动实现 [pca9555.c](https://github.com/apache/nuttx/blob/master/drivers/ioexpander/pca9555.c)。
  - **<span class="reference">ioexpander</span>** **驱动实例化**：可参考仿真平台（SIM）的 <span class="reference">ioexpander</span> 实例化代码 [sim\_ioexpander.c](https://github.com/apache/nuttx/blob/master/boards/sim/sim/sim/src/sim_ioexpander.c)。

## 2、<span class="reference">lower\_half</span> 方式

<span class="reference">lower\_half</span> 方式是一种更直接的 GPIO 驱动实现，其代码通常与特定的板级（Board）配置绑定。在这种模式下，您需要直接实现 <span class="reference">gpio\_dev\_s</span> 结构体定义的回调函数。

这些回调函数通常会调用芯片厂商提供的底层 GPIO API（即 <span class="reference">chip gpio api</span>）。openvela 对 <span class="reference">chip gpio api</span> 没有强制规范，开发者只需遵循 openvela 的编码风格，并确保实现芯片所支持的全部 GPIO 功能即可。

![](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005743472_004.png)

### 依赖头文件

在 <span class="reference">lower\_half</span> 方式下，需要实现的接口定义在如下头文件中，在编写 Board GPIO 驱动时需要包含该头文件：  

    //配置依赖：CONFIG_DEV_GPIO=y
    #include <nuttx/ioexpander/gpio.h>

### 核心接口实现

您需要为 <span class="reference">gpio\_lowerhalf\_s</span> 结构体填充以下回调函数指针。

| **函数原型**                                                        | **描述**                  |
| :-------------------------------------------------------------- | :---------------------- |
| <span class="reference">int go\_read(dev, \*value)</span>       | 读取引脚电平。对所有引脚类型都是必需的。    |
| <span class="reference">int go\_write(dev, value)</span>        | 写入引脚电平。仅对输出类型的引脚有效。     |
| <span class="reference">int go\_setpintype(dev, pintype)</span> | 设置引脚类型，如输入、输出、中断等。      |
| <span class="reference">int go\_attach(dev, callback)</span>    | 附加一个中断回调函数。仅对中断类型的引脚有效。 |
| <span class="reference">int go\_enable(dev, enable)</span>      | 使能或禁用引脚中断。              |

### 注意事项

1.  <span class="reference">go\_write()</span> 函数仅需为输出类型的引脚实现。
2.  在实现 <span class="reference">go\_enable()</span> 时，必须检查是否已通过 <span class="reference">go\_attach()</span> 注册了回调函数，否则不应允许使能中断。
3.  <span class="reference">go\_attach()</span> 和 <span class="reference">go\_enable()</span> 仅需为支持中断的引脚类型实现。
4.  **重要**：在实现 <span class="reference">go\_setpintype()</span> 时，除了配置硬件，您还**必须**手动更新 <span class="reference">dev-\>gpio.gp\_pintype</span> 成员变量。

### 示例代码

<span class="reference">lower\_half</span> 驱动与板级代码紧密相关。您可以在 <span class="reference">boards</span> 目录下找到适用于不同架构和板卡的实现。例如，树莓派 Pico（RP2040 芯片）的 <span class="reference">lower\_half</span> GPIO 驱动：[rp2040\_gpio.c](https://github.com/apache/nuttx/blob/master/boards/arm/rp2040/raspberrypi-pico/src/rp2040_gpio.c)。

### 设备注册

要使 GPIO 设备对用户空间可见，必须进行设备注册。注册过程会将您的南向接口实现与一个设备文件名（如 <span class="reference">/dev/gpio0</span>）关联起来。

您可以使用以下函数进行注册：

  - **<span class="reference">int gpio\_pin\_register(FAR struct gpio\_dev\_s \\\*dev, int minor)</span>**
    
      - 通过次设备号（minor number）注册设备，设备名为 <span class="reference">/dev/gpio</span> + <span class="reference">minor</span>。

  - **<span class="reference">int gpio\_pin\_register\_byname(FAR struct gpio\_dev\_s \\\*dev, FAR const char \\\*pinname)</span>**
    
      - 通过指定名称注册设备，设备名为 <span class="reference">/dev/</span> + <span class="reference">pinname</span>。

> **提示**：如果您使用 <span class="reference">ioexpander</span> 方式，可以直接调用 [gpio\_lower\_half()](https://github.com/apache/nuttx/blob/master/drivers/ioexpander/gpio_lower_half.c) 函数，它内部封装了注册逻辑。

# 二、芯片级 GPIO API (<span class="reference">chip gpio api</span>)

芯片级 API 是最底层的硬件抽象层，负责直接操作 GPIO 寄存器。它需要实现芯片所支持的全部 GPIO 功能，包括引脚模式配置、电平读写、复用功能切换等。

openvela 对此层级没有定义标准接口。芯片厂商或开发者需要根据具体芯片的数据手册，自行实现这部分功能，并遵循 openvela 的编码规范。

  - **参考实现**：您可以参考 [STM32 系列芯片的 GPIO 底层实现 stm32\_gpio.c](https://github.com/apache/nuttx/blob/master/arch/arm/src/stm32/stm32_gpio.c)。

# 四、与其他操作系统的对比

下表简要对比了 openvela、Linux 和 Zephyr 在 GPIO 子系统上的主要差异。

| **特性**          | **openvela**                                                                                                                           | **Zephyr**                                              | **Linux**                                                                               |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------ | :-------------------------------------------------------------------------------------- |
| **北向接口**        | 字符设备 (<span class="reference">/dev/gpiox</span>)                                                                                       | 自定义系统调用, 需设备树配合                                         | <span class="reference">libgpiod</span> (现代), <span class="reference">sysfs</span> (传统) |
| **南向接口**        | <span class="reference">struct gpio\_dev\_s</span> (lower\_half) <span class="reference">struct ioexpander\_dev\_s</span> (ioexpander) | <span class="reference">struct gpio\_driver\_api</span> | <span class="reference">struct gpio\_chip</span>                                        |
| **其他驱动子系统使用**   | <span class="reference">ioexpander</span> 宏接口                                                                                          | <span class="reference">device\_get\_binding()</span>   | <span class="reference">gpio\_to\_chip()</span>                                         |
| **Pin Control** | 无独立子系统，功能分散在 GPIO 驱动中                                                                                                                  | 支持                                                      | 独立的 Pinctrl 子系统                                                                         |
| **配置系统**        | Kconfig                                                                                                                                | Kconfig, Device Tree                                    | Kconfig, Device Tree                                                                    |
