本指南详细阐述了 openvela 射频接口层（Radio Interface Layer, RIL）的架构，并为 Modem 厂商提供了在 openvela 系统中适配和集成其 <span class="reference">vendor-ril</span> 的完整流程与技术要求。

# 一、概述

openvela 射频接口层 (Radio Interface Layer, RIL) 是一套完整的 Telephony 功能解决方案，其设计深受 Android RIL 架构启发。它最初为 openvela QEMU 模拟器开发，现已推广至实体硬件产品。

本节介绍 openvela RIL 的核心架构、组件职责以及厂商适配的协作模式。

## 1、RIL 架构与组件

openvela RIL 架构由三个核心组件构成，它们协同工作，连接上层 Telephony 框架与底层 Modem 硬件。

  - **<span class="reference">libril</span>**: 作为接口库，负责接收上层 Telephony 框架 (oFono) 的 Socket 请求，并将其转发给 <span class="reference">rild</span> 守护进程。其实现参考了 Android 7.0 版本。
  - **<span class="reference">rild</span>**: 作为核心守护进程，充当 <span class="reference">libril</span> 和 <span class="reference">vendor-ril</span> 之间的桥梁。它管理两者间的通信链路，并将请求分发给 <span class="reference">vendor-ril</span> 处理。
  - **<span class="reference">vendor-ril</span>**: 作为厂商特定的实现，直接与底层 Modem 硬件或 QEMU 模拟器 (<span class="reference">modem\_simulator</span>) 交互，执行具体的通信操作。openvela 提供的参考实现 (<span class="reference">reference-ril</span>) 主要参照了 Android 13 的代码。

![](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005750511_004.png)

## 2、协作模式与适配策略

为简化不同硬件平台的适配工作，openvela RIL 采用标准化与定制化分离的策略，明确了 openvela 与 Modem 芯片厂商的职责分工。

  - **通用组件 (openvela 维护)**: openvela 负责维护和提供通用的 <span class="reference">libril</span> 库和 <span class="reference">rild</span> 守护进程。这些组件在所有搭载 openvela 的产品中保持一致，厂商无需修改。
  - **定制模块 (<span class="reference">vendor-ril</span>) (Modem 厂商开发)**: Modem 芯片厂商仅需专注于开发和实现与其硬件相适配的 <span class="reference">vendor-ril</span>。这部分代码需要处理特定芯片的硬件接口、AT 命令集、通信协议和控制逻辑。

该协作模式通过标准化通用组件、分离定制化模块，旨在大幅降低 Modem 厂商的适配成本，加速其产品融入 openvela 生态系统。

# 二、代码库结构

## 1、代码目录简介

openvela RIL 的源代码位于 <span class="reference">external/ril</span> 仓库，其核心代码存放在 <span class="reference">external/ril/ril</span> 子目录中。

### 代码库路径

    vela_source_code/external/ril

顶层的 <span class="reference">external/ril</span> 目录主要存放 RIL 项目的顶层编译配置文件，而实际的核心源代码则位于 <span class="reference">external/ril/ril</span> 子目录中。

### 核心目录结构

    .
    ├── include         # RIL 公共头文件，定义核心数据结构和接口
    ├── libril          # 通用 libril 库实现，负责与上层框架通信
    ├── librilutils     # RIL 通用工具函数库
    ├── reference-ril   # QEMU 模拟器专用的参考实现 (厂商不应修改)
    └── rild            # RIL 守护进程 (rild) 的主程序入口

## 2、<span class="reference">reference-ril</span> 的作用与模块化设计

<span class="reference">reference-ril</span> 目录提供了一个基于 AT 命令的 RIL 参考实现，其**核心目的仅在于作为示例**，用以展示 <span class="reference">vendor-ril</span> 的基础结构、接口规范以及与 <span class="reference">rild</span> 的交互逻辑。在当前代码库中，该实现专为 QEMU 模拟器 (<span class="reference">modem\_simulator</span>) 环境定制。

> **注意：**
> 
> <span class="reference">reference-ril</span> **绝非**设计用来存放厂商最终产品代码的位置。

为了提升代码的可读性和可维护性，<span class="reference">reference-ril</span> 将功能按模块拆分，主要包括：

  - <span class="reference">at\_call.c</span>: 通话 (Call) 相关 AT 命令处理
  - <span class="reference">at\_data.c</span>: 数据业务 (Data) 相关 AT 命令处理
  - <span class="reference">at\_modem.c</span>: Modem 控制相关 AT 命令处理
  - <span class="reference">at\_network.c</span>: 网络 (Network) 相关 AT 命令处理
  - <span class="reference">at\_sim.c</span>: SIM 卡相关 AT 命令处理
  - <span class="reference">at\_sms.c</span>: 短信 (SMS) 相关 AT 命令处理
  - <span class="reference">at\_ril.c</span>: RIL 请求分发与主逻辑
  - <span class="reference">atchannel.c</span>: AT 命令收发通道管理

这种模块化设计通过 <span class="reference">on\_request\_\*</span> 和 <span class="reference">try\_handle\_unsol\_\*</span> 等分发函数，将 RIL 请求和主动上报路由到相应的模块文件中处理。

> **开发建议：**
> 
> Modem 厂商在开发自己的 <span class="reference">vendor-ril</span> 时，应遵循此模块化结构。这能确保代码逻辑清晰、职责分明，极大地便利后续的开发、调试与长期维护工作。

# 三、Vendor RIL 适配工作流

适配工作的核心是将厂商特定的 <span class="reference">vendor-ril</span> 正确集成到 openvela 构建系统中。请严格遵循以下步骤。

## 步骤 1：创建目录

> **注意**
> 
> **严禁**以任何形式直接修改、删除或替换 <span class="reference">external/ril/ril/reference-ril</span> 目录内的任何内容。

建议您在芯片专属的 <span class="reference">vendor</span> 目录下创建一个新的 <span class="reference">vendor-ril</span> 目录，用于存放您的定制 RIL 代码。

### 目录路径示例

    vendor/<厂商名称>/<芯片平台名称>/<vendor-ril>/

## 步骤 2：部署代码与编译脚本

将您开发的所有 <span class="reference">vendor-ril</span> 源代码文件复制到上一步创建的目录中。同时，在此目录内添加相应的构建系统配置文件（例如 Kconfig 或 <span class="reference">CMakeLists.txt</span>），以确保构建系统能够正确编译和链接您的代码。

### 目录文件示例

    $ tree sample_vendor_ril/
    sample_vendor_ril/
    ├── CMakeLists.txt
    ├── Kconfig
    └── sample_vendor_ril
        ├── at_call.c
        ├── at_call.h
        ├── atchannel.c
        ├── atchannel.h
        ├── at_data.c
        ├── at_data.h
        ├── at_modem.c
        ├── at_modem.h
        ├── at_network.c
        ├── at_network.h
        ├── at_ril.c
        ├── at_ril.h
        ├── at_sim.c
        ├── at_sim.h
        ├── at_sms.c
        ├── at_sms.h
        ├── at_tok.c
        ├── at_tok.h
        ├── misc.c
        ├── misc.h
        ├── MODULE_LICENSE_APACHE2
        └── NOTICE
    
    1 directory, 24 files

## 步骤 3：集成到 openvela 构建系统

您需要通过 <span class="reference">Kconfig</span> 和 <span class="reference">CMakeLists.txt</span> 将您的 <span class="reference">vendor-ril</span> 集成到系统构建流程中。构建系统将自动把通用的 <span class="reference">libril</span>、<span class="reference">rild</span> 与您的 <span class="reference">vendor-ril</span> 编译链接，最终生成一个适配目标硬件的 <span class="reference">rild</span> 守护进程。

### 3.1 停用模拟器 RIL

首先，通过 Kconfig 配置系统，**禁用**默认的 QEMU 模拟器 RIL (<span class="reference">CONFIG\_GOLDFISH\_RIL</span>)。

### 3.2 添加 Kconfig 选项

在您 <span class="reference">vendor</span> 目录的顶层，创建一个 <span class="reference">Kconfig</span> 文件，为您的 RIL 添加一个启用选项。

**Kconfig 示例 (<span class="reference">vendor/\<厂商\>/\<平台\>/Kconfig</span>)：**  

    #
    # For a description of the syntax of this configuration file,
    # see the file kconfig-language.txt in the NuttX tools repository.
    #
    
    config SAMPLE_VENDOR_RIL
            tristate "Enable SAMPLE_VENDOR_RIL"
            default n
            depends on RILD
            ---help---
                    Enable sample vendor ril

### 3.3 创建 <span class="reference">vendor-ril</span> 的 CMakeLists.txt

在您的 <span class="reference">vendor-ril</span> 目录中 (<span class="reference">vendor/\<厂商\>/\<平台\>/vendor-ril/</span>)，创建一个 <span class="reference">CMakeLists.txt</span> 文件来描述如何编译您的源代码。此 <span class="reference">CMakeLists.txt</span> 仅需关注 <span class="reference">vendor-ril</span> 自身的源文件。

**CMakeLists.txt 示例 (<span class="reference">vendor/\<xxx\>/\<platform\>/\<sample\_vendor\_ril\>/CMakeLists.txt</span>)：**

# 四、开发注意事项与建议

## 1、关键注意事项

  - **模拟器与真机的差异**: <span class="reference">reference-ril</span> 是为受限的 QEMU 模拟器环境设计的。在移植到实体硬件时，您必须考虑更复杂的真实场景，例如更全面的错误处理、信号强度动态变化、网络切换逻辑等。
  - **移除模拟器专用代码**: <span class="reference">reference-ril</span> 中包含一些模拟器特有的代码（例如 <span class="reference">ENABLE\_MODEM</span> 宏）。在适配您的硬件时，您必须识别并移除这些代码。
  - **健壮的状态管理**: <span class="reference">reference-ril</span> 为简化实现，使用了一些全局变量来保存状态。在实体产品中，这种做法可能导致竞态条件和系统不稳定。我们强烈建议您在 <span class="reference">vendor-ril</span> 中采用更健壮的状态管理机制（例如基于上下文的结构体）。

## 2、开发建议

  - **限制修改范围**: 请将您的代码修改严格限制在自己的 <span class="reference">vendor-ril</span> 目录内。<span class="reference">libril</span> 和 <span class="reference">rild</span> 是跨平台共享的通用组件。如果必须修改通用代码，请创建 Patch 并提交给开发人员进行评估和合入。
  - **完善硬件特定功能**: <span class="reference">reference-ril</span> 中的某些功能是为模拟器模拟的（如 <span class="reference">enable modem</span>）。您需要根据实际硬件的行为，在 <span class="reference">vendor-ril</span> 中实现这些功能的完整逻辑。
  - **适配设备节点**: <span class="reference">reference-ril</span> 打开的设备节点是 <span class="reference">/dev/ttyV0</span>，这是 Goldfish 模拟器提供的虚拟串口。您必须将其修改为您的 Modem 硬件在系统中的实际设备节点（例如 <span class="reference">/dev/ttyS1</span> 或 <span class="reference">/dev/ttyUSB0</span>）。

# 五、接口要求

您的 <span class="reference">vendor-ril</span> 实现必须遵循 openvela Telephony 的接口规范。

  - **请求分类**: RIL 请求分为 **必选** 和 **可选** 两类。您的实现**必须**支持所有必选请求，**建议**支持可选请求。

  - **文档优先原则**: 如果 <span class="reference">reference-ril</span> 的实现与接口文档存在差异，**请始终以接口文档为准**。
    
      - 例如，<span class="reference">reference-ril</span> 的 <span class="reference">at\_network.c</span> 中 <span class="reference">requestSetPreferredNetworkType</span> 函数可能沿用了 Android 原生实现，而未遵循文档要求的 <span class="reference">RIL\_PreferredNetworkType</span> 枚举。在这种情况下，您应参考文档进行正确开发。

# 六、RIL 适配准入测试

完成 <span class="reference">vendor-ril</span> 适配后，您可以使用 <span class="reference">RILTEST</span> 工具进行准入测试，以验证实现的正确性。

## 1、测试步骤

1.  **关闭 oFono**: <span class="reference">RILTEST</span> 工具与 <span class="reference">oFono</span> 服务存在冲突，不能同时运行。请在 Kconfig 中**禁用** <span class="reference">CONFIG\_OFONO</span> 选项。

2.  **开启 RILTEST**: 在 Kconfig 中**启用** <span class="reference">CONFIG\_RIL\_TEST</span> 选项。

3.  **重新编译系统**：执行完整的编译流程，生成包含 <span class="reference">RILTEST</span> 的固件并烧录至设备。

4.  **推送测试脚本**: 将 [run\_testcase.sh](https://github.com/open-vela//docs/https:/github.com/open-vela/docs/blob/dev/zh-cn/device_dev_guide/connection/telephony/ril_adaptation_guide.md/run_testcase.sh) 脚本通过 <span class="reference">adb</span> 推送到设备的数据分区。  
    
        adb push run_testcase.sh /data/

5.  **执行测试**: 通过 <span class="reference">adb shell</span> 登录设备并运行测试脚本。  
    
        adb shell "sh /data/run_testcase.sh"

​ 测试工具将自动执行一系列 RIL 命令并验证 Modem 的响应，帮助您快速定位和修复实现中的问题。
