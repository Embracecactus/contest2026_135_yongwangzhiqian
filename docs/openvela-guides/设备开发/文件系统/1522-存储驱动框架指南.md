# 一、概述

本文档旨在为芯片和板卡供应商提供 <span class="reference">openvela</span> 存储驱动框架的整体介绍，帮助开发者理解其核心架构、驱动模型以及与系统的交互方式。掌握这些概念是进行具体驱动开发的基础。

<span class="reference">openvela</span> 的存储框架为各类非易失性存储介质（如 eMMC、SD 卡、NOR/NAND Flash 等）提供了统一、可扩展的接入层。

# 二、驱动模型概览

<span class="reference">openvela</span> 系统将设备驱动主要分为三类：字符设备、块设备和特殊设备。针对存储介质，系统主要采用以下两种驱动模型：

  - **块设备 (Block Device)** **驱动**
    
    用于管理可按固定大小的块（扇区）进行寻址和读写的存储介质，如 eMMC 和 SD 卡。这类驱动是承载 FAT、LittleFS 等文件系统的理想选择。
    
      - **字节流访问代理**：虽然块设备本身不支持字节流访问，但当应用层尝试以文件方式打开块设备节点时，<span class="reference">openvela</span> 内核会通过 **BCH(Block-to-Character)** 模块自动创建一个临时的字符设备代理。该代理负责将字节流请求转换为对底层块设备的块操作，从而对上层应用屏蔽了实现差异。

  - **MTD (Memory Technology Device)** **驱动**
    
    专为各类闪存芯片（如 NOR/NAND Flash）及其他存储技术（如 EEPROM、RRAM）设计。MTD 模型充分考虑了闪存介质的特性，例如**先擦后写**和有限的擦写寿命。
    
      - **字节流访问代理**：与块设备类似，MTD 设备也可以通过代理机制供上层进行字节流访问。当应用打开 MTD 设备节点时，内核会按需创建：
        
          - 一个临时的 **FTL(Flash Translation Layer)**，将 MTD 设备模拟成块设备。
          - 一个临时的 **BCH** 代理，完成从模拟块设备到字符设备的转换。

# 三、上下半部 (Upper/Lower Half) 架构

为了最大化代码复用和提升跨平台移植性，<span class="reference">openvela</span> 的驱动普遍采用**上半部/下半部**分层架构。

![img](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005745137_002.png)

  - **上半部驱动 (Upper Half)**
    
      - **职责**：负责实现与平台无关的通用逻辑，为上层应用提供标准的 POSIX 接口（如 <span class="reference">open</span>、<span class="reference">read</span>、<span class="reference">write</span> 等）。
      - **特点**：由 <span class="reference">openvela</span> 系统提供，开发者通常无需修改。它通过一组标准的操作函数指针与下半部驱动交互。

  - **下半部驱动 (Lower Half)**
    
      - **职责**：负责实现与具体硬件平台相关的逻辑，直接操作芯片的寄存器和控制器。
      - **开发任务**：**芯片或板卡供应商 (Vendor) 的主要职责是编写下半部驱动**。您需要实现一套由上半部驱动定义的操作接口（<span class="reference">struct mtd\_dev\_s</span> 或 <span class="reference">struct block\_operations</span>），并将硬件的特定行为封装在这些接口函数中。

这种架构将硬件差异完全隔离在下半部，使得 <span class="reference">openvela</span> 的核心存储逻辑可以在不同芯片和硬件平台上无缝复用。

# 四、与虚拟文件系统 (VFS) 的交互

所有存储驱动最终都会被注册到 <span class="reference">openvela</span> 的虚拟文件系统 (Virtual File System, VFS) 中，通常位于 <span class="reference">/dev</span> 目录下，从而成为应用层访问的入口。

![img](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005745270_003.png)

应用层访问存储设备主要有两种路径：

  - **通过文件系统挂载进行访问**：
    
    这是最常见的使用方式。用户通过 <span class="reference">mount</span> 命令，将一个块设备（或经 FTL 模拟的 MTD 设备）、一种文件系统类型（如 LittleFS）和一个挂载点目录关联起来。挂载成功后，应用即可使用标准文件操作（<span class="reference">fopen</span>、<span class="reference">fread</span>、<span class="reference">fwrite</span> 等）来访问和管理存储介质上的文件与目录。
    
    ![img](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005745360_004.png)

  - **通过设备节点直接访问**：
    
    应用也可以直接 <span class="reference">open</span> 位于 <span class="reference">/dev</span> 目录下的设备节点（如 <span class="reference">/dev/mtdblock0</span>），并使用 <span class="reference">read</span>、<span class="reference">write</span> 和 <span class="reference">ioctl</span> 等接口进行底层I/O操作。这种方式绕过了文件系统，常用于分区格式化、固件烧录 (OTA) 或裸数据读写等场景。
    
    ![img](https://vela-open-doc.cnbj1.mi-fds.com/vela-open-doc/1781005745456_005.png)
