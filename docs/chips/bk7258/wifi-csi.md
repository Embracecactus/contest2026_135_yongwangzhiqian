# BK7258 原始 CSI 采集契约

范围是 manifest 固定的 Beken `v3.1.1.9`。芯片适配保留原始采样，主机完成
记录、幅度分析和可选的 RuView 转发。板型和诊断 profile 以
`boards/bk7258/CONFIGS.md` 为准；编译和主机协议检查不构成实板检测验收。

已完成 AIDK 原始采集的数据质量验证，结果与边界见
[2026-10-31 实板记录](../../verification/bk7258/2026-10-31-wifi-csi.md)。

## 所有权与生命周期

CP SDK 必须启用 `CONFIG_WIFI_CSI_EN`，由其构建选择 `libwifi_csi.a`。
AP 复用既有 Wi-Fi 控制 worker，所有 SDK 调用、原生 NuttX UDP 发送均位于
logical CPU0。CP 的 `bkwifi csi` 通过既有 RPMsg 控制链发送请求。
CSI profile 的控制协议版本为 5；普通 profile 保持版本 4。两种角色必须成对更新。

采集要求 STA 已连接。CSI 持有独占 radio lease，拒绝扫描、monitor 和重新配网；
正常 STA 收发继续用于导出。16 项队列的生产者是 SDK 串行回调，消费者是
Wi-Fi worker。回调只做校验和有界复制，不分配内存、不打印、不发送网络数据。
worker 每 10 ms 排空队列，单次最多处理 16 项。默认请求间隔为 40 ms，
实际回调频率取决于空口流量，不能用请求间隔代替实测帧率。

诊断采集开始前关闭 STA 省电并尝试发送初始状态包，避免休眠间隔影响逐帧观察，
也将启用 CSI 前的导出连通性纳入证据。该诊断关联保持唤醒直到断开或复位；
不宣称省电性能，不改变普通产品配置。

采集时长范围 1–600 秒；到时自动停止。停止失败时关闭接收门，但保留 socket、
active 状态及 radio lease，供显式重试或到期清理。关闭接收门并等待在途回调
退出后排空队列，在控制器仍可发送时发布数据流终态，再停止控制器、释放资源。
控制结果的 active 仅在硬件清理成功后清零。AP 退出时也请求清理。
终态快照有界重复三次，相隔 20 ms；它是幂等计数水位，数据帧不重发。
UDP socket 配置一秒 `SO_LINGER` 上限，避免失去 TX 路径后关闭无限等待。

## SDK 数据边界

`wifi_csi_info_t` 的 `len` 位于偏移 22，数据 union 位于偏移 32，结构大小 864。
固定 SDK 的 `csi_info_read` 将 `len` 用作采样项数；原始数据每项是 `uint32_t`。
适配只接受 `data_type=0`、`1 <= len <= 52`，发送恰好 `len * 4` 字节。
不输出 padding、未使用的 union 尾部或其他内存。无效长度和类型单独计数。

模式 bit 0 开启原始回调，bit 1 会逐项打印。诊断使用 mode=1、STA identity=1，
关闭逐项打印和厂商运动算法。默认只请求 NON_HT；可显式选择 HT_MM 或两者。

主机按固定库 `csi_alg_data_2_abs` 的位提取方式解释两个相邻的有符号 13 位分量
（bits 0–12、13–25），保留完整原始字。该库的幅值计算还乘以共同因子 8；
主机使用归一化幅度形状，省略这个共同因子。分量的 I/Q 命名、相位方向与真实
硬件输出的一致性仍需实测；不能直接宣称 BK 数据可复用 ESP32 的相位标定或模型。

## BCSI v1 导出

每个 UDP 数据报由 64 字节小端头部和 `count` 个原始小端 32 位字组成。
以 `chips/bk7258/include/bk7258_wifi_csi.h` 为唯一字段布局。

| 字段 | 含义 |
|---|---|
| magic / version | `BCSI` / 1 |
| kind | 1 为数据；2 为开始或结束计数快照，此时 count=0 |
| session / sequence | 每次启动的会话号、打开接收门后的回调序号 |
| timestamp_us | SDK 的本机 32 位接收时间；主机处理回绕 |
| callbacks / invalid / queue_drops | 已接收回调、无效数据、队列满丢弃 |
| sent / send_errors | UDP 栈接受的数据报序号、发送失败次数；不是远端 ACK |
| count / data_type | 实际采样项数、原始类型 |
| rssi / channel / format / bandwidth / mac | 本帧元数据 |
| active / uptime_ms | 发送时采样接收门是否打开、从启动计算的时间；硬件清理状态另见控制命令 |

记录器保留数据报原始 base64、接收时间和来源地址，使用独占创建，拒绝覆盖已有文件。
缺少有效 CSI 时返回退出码 3。终态包缺失时，传输丢失统计只覆盖最后收到的
UDP ordinal，不能推断尾部丢失；拿不到发射端总帧数时，回调之前的无线丢帧率未知。

## 一次对照实验

在与设备同一局域网的电脑运行接收器；Windows/WSL 环境优先在 Windows 原生
Python 下监听电脑的 WLAN 地址，避免未经配置的 WSL UDP 转发。
目标地址必须在设备上实际可达。若无线客户端之间不可达，可选电脑的可路由有线
地址；经 NAT 收包时，`--source` 应填实际收包源地址或省略，不能假定它等于设备
的 DHCP 地址。

```bash
python tools/bk7258/bk7258.py csi receive --bind 0.0.0.0 --port 5505 \
  --source DEVICE_IP --seconds 70 --label empty --output empty-calibration.jsonl
```

在 CP 控制台连接 Wi-Fi 后开始 60 秒采集：

```text
bkwifi connect
bkwifi csi start HOST_IP 5505 60000 40 1
bkwifi csi status
bkwifi csi stop
```

保持设备、路由器、家具及无线信道不变，另录一组空房、一组静坐、一组走动。
每组使用新的输出文件和准确的 label（`empty`、`still`、`moving`）。第一组空房
用于标定，评估必须用另外的记录，不能在同一记录上标定并报告检测准确率。

```bash
python tools/bk7258/bk7258.py csi analyze --baseline empty-calibration.jsonl \
  --input empty-evaluation.jsonl --input still.jsonl --input moving.jsonl
```

分析先报告长度分布、实际帧率、时间间隔波动和分层计数；同一发射源、信道、
PHY 格式、带宽、长度才能共享标定。空房样本前半拟合幅度参考，后半确定阈值。
每 2 秒输出存在变化和运动候选分数及按人工 label 计算的窗口准确率。
它们是当前房间的实验性启发式，家具、干扰和其他人也能触发变化；静止人体
存在与运动必须分别验证，不能由一次走动检测推导出静坐检测有效。

## RuView 转发

接收器可添加 `--ruview 127.0.0.1:5005 --node-id 58`，在保留原始记录之后，
将每个有效数据报转换为 RuView ADR-018（20 字节头、1 天线、实际子载波数量）。
两个 13 位分量用固定除数 32 量化成 int8；不进行逐帧自适应缩放。BK 接口没有
noise floor，因此该字段保留 0，不能用于声称真实信噪比。原始 SDK 时间不在
ADR-018 头中；需要时间分析时使用 BCSI 原始记录。
RuView 端应显式选择硬件数据源（如官方指南的 `CSI_SOURCE=esp32`），关闭
自动回退模拟；仅看到演示画面不能证明接入了本次真实采集。

参考：
[RuView 数据序列化](https://github.com/ruvnet/RuView/blob/main/firmware/esp32-csi-node/main/csi_collector.c)、
[官方能力边界](https://github.com/ruvnet/RuView/blob/main/docs/user-guide.md)。
兼容数据格式不证明检测效果；此阶段不验收呼吸、心率、动作分类或人体关键点。

## 单板、无外部无线节点的可行性调查（2026-11-01）

该目标要求本机发射和观测环境反射，不能用被动接收邻近设备的帧代替。
现有 STA/ACK 采集的成功不能证明这个目标可行；SDK 没有现成公开接口也不能
直接证明硬件不可能实现。当前已完成十一版诊断固件的同板检查：前六版的
发射期 ADC 冻结已通过 RC 强制请求解除；第九版起能在变化的 TX DAC
波形期间取得变化的 RF ADC 调试字，并收到本机帧发送完成回调。
这证明内部采样路径有进展，尚不证明天线侧具备环境反射输入。
尚未取得单板环境回波，不能开始声称人体存在、运动或生命体征检测有效。

固定 SDK 的本地只读检查确认：

- `cp/middleware/soc/Kconfig` 中 BK7258 选择 `SOC_BK7236XX`，适用
  `cp/components/bk_phy/src/cli_phy.c` 注册的
  `la rf_adc_40M/rf_adc[_80M]/fe_adc/rf_dac/fe_dac` 调试命令。
- `cp/components/bk_libs/bk7258/libs/libbk_phy.a` 的 `la_driver.c.obj`
  存在真实实现：`cmd_la_sample_test` 为 0x100 字节，`la_sample_print`
  为 0x264 字节。对象反汇编确认命令分派到五种采样选择。
- `la_sample_print` 使用 DMA 抓取缓冲及调试信号选择，申请最多 128 KiB，
  并在关中断区逐字打印。它不是可直接复用的连续采集接口；实验适配需要
  小缓冲、明确超时、恢复被改动的选择/时钟状态，并在正常调度下导出数据。
- `bk7011_*sample_mac_out_for_ate` 是另一路 MAC 调试采样；不能将其返回值
  直接解释为 RF ADC IQ。其 get 函数还存在无超时等待，不能直接用作实验读取。
- 存在 `rc_drv_set_rx_mode_enrxsw` 等内部射频控制符号，但名称和寄存器位
  不证明可以同时发射和接收。当前未建立可用的天线侧收发并行控制契约。

上述项目是静态证据；随后采用独立的有界适配进行了下述实板实验，
没有直接调用厂商的大缓冲打印命令，也没有改变天线 RF 开关。
原库 SHA256 为
`0def7fb82dc69463003a4c72f97be665a49563b51b11171d7d66fc1d07a43502`；
只读提取的对象、反汇编与版本记录保存在工作区
`out/bk7258-single-radio-20261101/`，不作为可发布的厂商源码。

单板实验的先后判据：

1. 建立有界 RF ADC 抓取与恢复，确认样本位宽、布局、采样时钟和有效长度。
2. 使用本机已知发射时序，判定发射窗口内接收通路是否输出天线侧的有效信号。
   有数据、非零数据或内部回环相关峰，均不足以认定观察到了环境反射。
3. 对照本机停止/开始发射、反射物静止/受控移动，区分内部泄漏、环境外部
   发射源和自身信号的反射。只有此关通过，才进入运动或存在检测算法。

研究参考：Intel 的
[单设备 Wi-Fi 感知论文](https://arxiv.org/html/2508.02799v1)
在 AX211 上使用分开的发射/接收天线和底层采样实现感知，说明部分商用芯片
能通过底层开发实现单设备感知。它不能直接证明 BK7258 的 1x1 射频结构支持
相同路径，也不是可直接移植到 BK7258 的驱动。

### 单板实测与阻塞点

诊断命令为 `bkwifi rf <source> [words=256] [timeout_ms=100] [tx]`，
只由 `csi_cp` 开启 `CONFIG_BK7258_WIFI_RF_CAPTURE`，普通语音配置默认关闭。
CP 用内部 SRAM 保存最多 1,024 个原始 32 位字，检查尾部保护区，设置
10–500 ms 采样等待超时，并恢复 LA、PHY 时钟及调试选择。
`tx` 需要先运行 `bkwifi monitor start 6`。当前版本每次仅排队一帧
256 字节的广播数据，并等待发送完成回调，无需 STA 关联或 AP；未覆盖
发射功率、速率或持久化参数。广播完成不要求 ACK。
SDK 排队等待和 UART 导出不属于采样等待超时，`elapsed_ms` 是系统 tick
粒度的轮询耗时，不是波形采样周期，也不能据此推算采样率。

| 对照 | 实测 | 可得结论 |
| --- | --- | --- |
| 无连接、接收未启动 | 100 ms 超时，恢复和保护区通过 | 失败退出可用 |
| monitor 中的 `rf40` / `rf80` / `feadc` | 三种原始字均变化，记录连续且无哨兵残留 | 调试采样通路可用；环境 Wi-Fi 未隔离 |
| `fedac` 不发射 / 发一帧 | 前者超时，后者取得变化的发送数据 | 本机发射控制与发送侧采样相符 |
| `adctx` 混合 ADC / TX DAC | 信道 6、11 共 8 次，每次 1,024 字；TX 高半字有 73 个不同值，ADC 低半字仅 1 个值 | 当前 TX 窗口未观察到更新的接收样本 |
| `adctxon` 仅设置 TX 模式 `enrxadc` | 两信道共 3 次，`ddf90339 → ddf903b9` 确认 bit 7 写入生效，ADC 调试值仍冻结；寄存器及影子均恢复 | 单独设置 ADC 使能位不能解除接收采样暂停 |
| `rxhold` 保持接收时钟 | `force1: 00003108 → 0000f108`，ADC 触发匹配仍为 0 | RC、AHB、active、DSSS RX 时钟强制使能不足以取得输入 |
| `rxhold` 再使能接收模拟子链路 | `TX map: ddf90339 → ddf9bfb9`；低 10 位不变；第 5 版低半字 bit 15 有变化但 bit 10 始终为 0 | 控制写入生效，仍无接收触发条件下的数据变化 |
| `fehold` 改看 FE ADC / TX DAC | 第 6 版 1,024 字中发送触发匹配 1,024 次，接收触发匹配 0 次，低半字仅 1 个值 | FE ADC 采样位置也没有解除当前 TX 窗口的输入冻结 |

`adctx` 使用实验组合 `0x00065952`，将厂商 RF ADC 与 FE DAC 调试选择
放到同一抓取中，以发送侧触发。11 次混合抓取中，低半字的厂商 ADC 触发位
bit 10 全为 0，高半字的发送触发位 bit 28 全为 1。`rf40` 接收对照中的 ADC
触发位为 1 且数据变化。它支持“当前 TX 模式接收采样暂停”的解释，
尚不等同于完整 IQ 编码解析或所有硬件模式均不可能实现并发接收的证明。

全部恢复与保护区检查通过。没有连接家庭 Wi-Fi；monitor 接收到环境帧，
因此也没有声称完成了射频隔离环境或人体场景验收。没有调用 RF 校准流程、
修改 PA / 天线开关，或写入启动区、身份及校准分区。

代码、各版固件和日志在工作区 `out/bk7258-single-radio-20261101/`；
汇总为 `capture-summary.json`，每次实验有原始 UART、抓取结果及下载清单。

### 强制请求与发射测量输入（第 7–11 版）

`rxforce` 保存并设置 RC force_en / RX / TX 请求，临时使 RX、TX、force
三张映射一致，包含原 TX 映射与 RX 模拟子链路使能。天线开关、共享 LPF
和 PA 配置仍保留原值。第 8 版首先取得 1,024 次 RX 触发匹配与变化的
ADC 字，但 TX 高半字不变：强制模式下 TX ready 位常高，会提前触发。
第 9 版起同时要求 TX DAC 数据 bit 16，实测高低半字均变化；退出时先
强制 shutdown，再恢复所有映射、请求、时钟和 RAM 影子。

ADC8 的 `tssi` 命令复用 SDK ADC 锁和 32 点连续读取。第 7 版在第二块
返回 BUSY；第 8 版修正为只启动一次，由后续 read 重启中断交付。
第 10 版保留发送完成前的最后一段采样，`adc_samples` 可大于导出的
