> 操作：六次点击：五个阶段依次出现，最后出现真实等待与优化。TTS 对照表见备查 D。
详版讲解（问答或时间富余时用）：把刚才那一句拆开：第一步唤醒在 AP 上用 INT8 模型本地完成，每 300 毫秒判一次，连续两次才算；第二步录音整段交给云端识别；第三步进入官方 Agent，会先匹配音量、表情、停止这类固定指令，命中就不请求大模型；第四步复用官方 Agent 的语音通道、TTS 队列与播放器生命周期，由 Media 输出；第五步真正播完才重新收音，所以能免唤醒追问。最下面是九月原片里的真实等待：问完到开口要 11 到 27 秒，这是初赛后我们做时延工作的起点——先分阶段埋点。产品只启用 R1 的提前准备 Media；直接回答路径与 256 KiB 队列是研究配置。TTS 同板小样本对照后保留 MiMo。手机热点下曾记录 32.8 秒，网络条件不同，不能据此判定性能退步；778 端到端时延尚未复测。

## 06 唤醒模型（32 秒，含视频 0 秒；累计 2:17）

唤醒模型是我们自己训的：正例用多音色合成并校正发音，负例有近音词、半句话和噪声，按来源先切分再增强。训练直接调用设备上那份 C 前端提特征，训练和上板一致。公开内置基线 INT8 约 23 KB。另有所有者适配模型与九轮研究，不能把私人或合成数据成绩当作公开模型的多人唤醒率。

> 操作：三次点击：数据/增强/特征 → 模型/量化/上板 → 9 轮研究。
详版讲解（问答或时间富余时用）：唤醒模型是团队用自己的工具链训练的。数据 406 条：正例 62 条用 Kokoro 多音色合成，我们发现合成引擎把 vela 读成了 vɛlə，于是用分词器实际输出的 token 反解，改写成 open vila 后全部重新生成；负例包括近音词、半句、普通指令、公开语音和噪声，还有 72 条真实环境静音。先按来源切分训练、验证和测试，再做滑窗、难负例、电平和合成房间增强。关键一点：训练时在主机上编译设备的那份 C 前端代码来提特征，所以训练和上板看到的是同一种特征。模型是 32 通道 DS-CNN，频率步长 4 把理论运算量从 4.85M 降到 2.43M MAC；全 INT8 只有 23,640 字节，在 AP 上约 80 毫秒一次，arena 用了 40,692 字节。初赛后又做了九轮研究：两百多小时公开真人语料、真人预训练、困难负例、教师模型审计发音，合成测试命中从 127 提到 318/400，20.99 小时真人负流里 0 次误唤醒；但快语速、近音词有退步，也没有真人多人正例，所以不报真人多人唤醒率。这里讲的是公开内置基线；历史 775 用过非公开的所有者适配 P5，778 当前模型身份未核验，不混用这几种模型的结果。

## 12 三端安全（24 秒，含视频 0 秒；累计 5:27）

三端不靠同一个局域网互信：未认领设备自动开放有限时的 BLE 认领窗口，手机核对二维码证书指纹并证明一次性秘密；电脑用手机授予的独立密钥，在 USB 上跑 TLS；固件和小功能都要 P-256 签名，固件采用配对 A/B 与试运行回退；当前 778 尚未重做 App OTA 验收。

> 操作：一次点击出现表格。
详版讲解（问答或时间富余时用）：三端之间不靠“在同一个局域网”互信。未认领且空闲的设备会自动开放有限时的 BLE 认领窗口；手机先核对二维码里的设备证书指纹，再在 TLS 加密通道里证明持有一次性秘密。普通按键是 PTT，旧的八秒按住/松开仅用于只读回执恢复，并不打开首认领。电脑用手机授予的独立密钥，在原生 USB 上跑 TLS，只拿到被授予的权限，审批回执用这把密钥做 HMAC。云端走 HTTPS，证书校验不因性能关闭。固件由 MCUboot 用 ECDSA P-256 验签，CP 和 AP 成对试运行，设计有失败回退；634/767/770 的 OTA 记录分开保留，778 没有新增 App OTA 验收。小功能和 Skill 也要签名。
