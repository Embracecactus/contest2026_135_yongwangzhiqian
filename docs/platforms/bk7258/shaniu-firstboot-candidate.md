## 新的首用路径

工厂全量部署 → 固件消费显式工厂事务 → 初始化真实持久卷 → 本机生成设备
身份 → 两块圆屏显示 SN1 认领码 → App 扫码并先离线认领 → 在设备控制页打开
「Wi-Fi 与云服务」分别保存 Wi-Fi 和云模型/API Key → 设备异步联网。

认领不再要求 Wi-Fi 或云账号先有效。二维码包含完整证书指纹及当前窗口秘密，
不含私钥；不要把二维码、原始扫码结果或私有整片镜像发到公共仓库。
自签名本地身份仅与物理扫码绑定，不提供厂家真伪认证或硬件密钥不可提取保证。
云服务 API Key 仍由使用者提供，未内置作者账号。

## 工厂镜像与迁移边界

沿用现有 `build --board aidk_ai_toy --boot mcuboot ...` 与 `release full ...`
命令及原有签名、同板 base、来源和回滚预检。在 **release full** 参数末尾增加
`--factory-init`，只在指定测试板恢复工厂状态时使用。

该参数输出额外的 `*-factory.bin`，并在 release 结果中给出
`factory_operator`、推荐烧录路径和 SHA256。原 operator 与 `.bkpack` 保持原语义；
它们不能替代工厂产物。工厂衍生镜像仍绑定本板保留区域，不能跨板分发。
缺少同板独有数据或可信签名输入时不得以全 FF 或别人的整片内容补齐。

本次在旧布局的未分配区声明独立的 `factory_state`，不移动现有
`persistent_data`，也不使用 OTA/看门狗的 `reset_marker`。布局身份发生变化，
因此首次安装要走匹配本板的完整部署，不是跨布局普通 OTA。

工厂输出仅清理声明的 `usr_config`、`persistent_data` 与工厂事务区，
其他字节从已验证同板输入保持。校准尾区和 OTP 不在初始化权限中。
首启按 REQUESTED → FORMATTING → READY 记录进度；只有正式工厂事务允许
格式化。正常挂载失败、既有身份丢失或存储损坏不会自动重开认领权限。

运行时 `bkfactory mount` 是启动脚本内部消费者，不是普通用户手工补救命令。
正常首用过程中不应执行 `bkdata init`、`openssl` 或 `bkprov supply`。

## 手机使用

从本分支源码编译匹配 APK（JDK17/Android SDK35）：

```sh
cd android/shaniu-companion
./gradlew :app:assembleDebug
```

CI 的临时 debug 签名不一定与原手机 APK 一致。已有绑定需要保留时，优先用
原本地构建/签名环境更新，不要默认卸载旧 App 清空 Keystore。

打开首次绑定页，选择扫码添加设备，扫描屏幕二维码后选择对应蓝牙设备完成认领。
认领成功后回设备页建立控制连接，在「Wi-Fi 与云服务」读取真实设置。
修改 Wi-Fi 与云服务分别提交；未填写的新 API Key 表示保留当前服务的密钥，
改到新主机必须输入新的 Key，并由手机校验新服务 TLS。Wi-Fi 密码通过明确勾选
替换，勾选且留空才表示开放网络，避免把空字段误当成删除。

保存回执与联网/云认证结果分开显示。最终提交后断连时先回读，不自动重复提交。
旧授权文件入口仅供兼容，不是新设备主路径。

## K2 电源

保留单独长按 K2 三秒、松手关机；本地电源图示提示长按与正在保存。
合法意图被保存，先取消语音和网络工作，再等待持久化/资源安全边界。
不以 Agent 或云服务 ready 作为接受 K2 的前提。无法安全完成时明确报告失败，
不把超时当成提交完成。

底层仍使用现有 CP reboot-to-sleep 软关机机制，**不是新实现的硬件断电**。
K2 再开机、USB/电池差异、是否意外唤醒及整板电流需要本地实测。
普通关机不设置工厂标记，也不清理身份/owner/Wi-Fi/云配置。
