# 2026-10-19 电脑工作台默认素材结果核对与恢复

按桌面功能顺序继续 N3 软件开发，OTA 保留最后。用户确认仍无实体 NFC 卡；
N2 软件合同定向复核未发现确定缺口，实卡触发及本地内容听感继续待验。
本次基于现有开发工作树增量修改，保留先前固件、Android、相机及其它改动。

## 行为变化

原网页缺少底层已有的默认操作取消、释放重试入口，且默认状态查询未传递操作
回执，不能区分本次结果和其它操作的最新状态。页面也只按 version_known
启用保存，未屏蔽保存中、结果未知或释放失败状态。

- 增加“核对本次操作”，复用既有 epoch/nonce 校验。发送请求前保留公开编号，
  HTTP 响应丢失时可查询，不自动重发。HTTP 默认状态接口允许既有 scope、nonce
  和 job ID；新 job ID 由设备状态取得，不从受理回执推断。
- “读取当前状态”显式读取最新作业并放弃本次回执匹配；目录与默认选择继续
  共用原作业所有者，切换后旧写入按钮失效。
- 取消仅在 pending/preparing 可用；committing/rendering 禁止取消。释放错误
  只开放显式恢复入口，恢复不重做保存或渲染，UNKNOWN 不显示成功。
- 默认保存仅在已完成且已知版本的刷新/选择结果上开放。提示分别说明保存、
  画面更新和释放状态，并保留原界面样式及本机 HTTP 权限边界。

## 验证

- 现有网页控制器回归先因缺少入口失败，补齐后通过；覆盖 uint64 版本、准确
  nonce、旧/未知结果、取消、释放恢复及丢失响应后不重发。未新增测试收集 ID。
- 9 项选择协议单测、12 项 HTTP 测试通过。HTTP 测试使用当前源码增量重建的
  原生资源安装 peer；不把主机文件/传输替身称为物理 USB 或 SD。
- 2 项 HTTP → 正式客户端 → 真实 TLS → 原生显示控制/存储/渲染状态机测试
  通过。验证待处理保存取消后无写入/渲染，重新保存完成，旧回执拒绝；释放
  恢复只增加一次卸载，写入/帧/挂载计数、默认版本及名称均不变，结果仍 UNKNOWN。
- Chrome 151.0.7922.34 运行正式 HTTP 服务、页面与控制器，以明确的合成设备
  作业驱动 13 次操作，完成刷新、核对、取消及释放恢复。1280/375 px 无横向
  溢出；375 px 明暗主题按钮均为 48 px 高；CSP 违规为 0。截图已检查。
- Black 24.10.0、Node 22.23.1 语法检查及 git diff --check 通过。

初次直接加载协议测试模块缺少 native peer 环境，4 项报设置错误；随后按既有
runner 执行相关原生路径。新增回执断言曾错误假设 ACK 含新 job ID，另有一项
错误要求释放后的卸载计数不变；均依据正式协议/计数定义修正。保留失败日志，
不计为产品缺陷或通过结果。
