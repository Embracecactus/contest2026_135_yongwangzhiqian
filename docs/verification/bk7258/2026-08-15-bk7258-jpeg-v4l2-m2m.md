# BK7258 JPEG V4L2 M2M bounded board verification

Date: 2026-08-15

## Result

PASS for the bounded standard V4L2 M2M contract and its final CP/AP validation
profile.  The exact signed `18.6.80` pair decoded the embedded baseline JPEG
twice through `/dev/video1`, exercised the negative and STREAMOFF paths,
released every JPEG resource, and reached a service-independent RPTUN
`CONNECTED` proof on the real T5-Board.

The earlier `18.6.79` board run is retained as causal evidence: JPEG itself
passed, but RPTUN remained `CONNECTING` because its state publication depended
on optional test or supervisor services.  The chip-level transport proof was
then added, host-tested, rebuilt as `18.6.80`, downloaded and reverified.

## Implementation contract

- The chip adapter uses NuttX `codec_register()` and the standard V4L2 M2M
  ioctl surface.  It advertises JPEG OUTPUT, YUYV CAPTURE, streaming and M2M
  only; MMAP, RGB565 and a private character-device ABI are not introduced.
- One open file owns the immutable SDK singleton.  A private one-thread work
  queue runs synchronous decode.  STREAMOFF and close prevent new work, wait
  for in-flight work, and return every residual buffer exactly once.
- A bounded parser admits only reviewed SOF0, 8-bit, one-scan,
  three-component 4:4:4/4:2:2/4:2:0 input.  DQT, DHT, SOF, SOS, DRI, entropy
  markers and exact EOI are checked before the immutable SDK sees the frame.
- The SDK reads `bytesused + 2048`, so input is copied into a grow-only aligned
  bounce with a zeroed 2048-byte guard.  CAPTURE ownership covers complete
  D-cache lines when a D-cache is active.
- A real SDK decode failure faults the handle and rebuilds the unique backend;
  local parse or capacity errors do not poison it.  An uncertain teardown is
  retained as an orphan rather than allowing a second owner.
- The current NuttX M2M upper half does not expose successful REQBUFS teardown
  to the lower half.  Formats therefore freeze after the first buffer-size
  query; close/reopen is the supported renegotiation boundary.
- RPTUN now owns a generation-qualified proof endpoint
  `bk7258-rptun-%08x`.  AP publishes NS CREATE, CP binds the exact generation
  and sends NS CREATE ACK, and each core stops its local bootstrap only after
  its own proof.  This is transport infrastructure and does not depend on
  `RPMSG_TEST` or `AP_SUPERVISOR`.

## Validation tuple

The dedicated pair uses compatibility ID
`t5_board_jpeg_m2m_validation_mcuboot_v1`:

- CP `t5_board_cp_jpeg_m2m_validation_mcuboot` uses UART0 plus the P0/P1 CP
  SWD route and preserved BL2 hold;
- AP `t5_board_ap_jpeg_m2m_validation_mcuboot` enables JPEG decode, M2M and
  the validator at `/dev/video1`, with 32 x 16 geometry and a 4096-byte input
  limit;
- coordinated standby, camera/DVP, LCD, DMA2D, JPEG encode, PSRAM and optional
  RPTUN test/supervisor services remain disabled.

The embedded 914-byte fixture has SHA-256
`7f8062346615782b1861b7cc3c86835117c3c73801249a90b671b23b7fe2d4af`.
It is baseline 4:2:2, single-scan, three-component JPEG.  The validator covers
single-open ownership, QUERYCAP/ENUM_FMT/TRY_FMT/S_FMT/G_FMT, MMAP rejection,
two USERPTR queues, valid decode, locally rejected truncated EOI, valid
recovery, unmatched OUTPUT STREAMOFF drain and close.

## Trust and download sequence

`7a7140df...aee4`, while the installed BL2 exposed `df8b7893...a26e`.
The public-trust preflight rejected it before the loader with
`writes_performed=false`; no Flash write occurred.  The pair was rebuilt with
the matching development public identity without changing the installed
BL1/BL2.

## Evidence boundary

- This is one 914-byte baseline 4:2:2 fixture at 32 x 16, USERPTR and one open
  owner.  Repeated nonconstant CRC/statistics are a bounded hardware smoke,
  not a host golden-pixel comparison or broad JPEG conformance result.
- Progressive, grayscale, multiscan, arithmetic and trailing-data JPEG,
  MMAP, source change, selectable stride, scaling, DMA2D/RGB conversion,
  camera/LCD integration, multiple opens, concurrent media and long stress
  remain outside this result.
- The truncated frame is rejected by the local parser; it does not inject a
  hardware decoder failure.
- The public-trust preflight proves compatibility with installed public
  identities, not a production OTP/eFuse trust root.  The loader success is
  not a Flash readback, slot-B/rollback exercise or independent cold-power
  cycle.
- The auto-debug run intentionally used `--no-console`; its serial files are
  zero length and `NO_CHECKPOINT` is expected.  The JPEG, cleanup, AP/CPU2 and
  RPTUN conclusions come from the two live SWD reads canonicalized above.
  COM4 was never opened.
