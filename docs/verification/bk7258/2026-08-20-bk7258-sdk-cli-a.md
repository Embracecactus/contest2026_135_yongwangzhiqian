# BK7258 SDK CLI-A verification

- Date: 2026-08-20
- Scope: SDK bundle verification, local install and manifest generation
- Conclusion: PASS for the first maintainer-facing CLI vertical slice

## Verified outcome

- `tools/bk7258/bk7258.py sdk verify|install|manifest` is the sole active
  interface for SDK bundle bytes and metadata.
- `_lib/sdk.py` owns exact bundle roots, symlink/special-file rejection,
  deterministic manifests, full byte hashes, provenance/libdriver/UART/profile
  binding, SDIO policy and no-overwrite atomic local installation.
- `build_dual_image.sh` and the transitional SDK rebuild importer use the new
  CLI. `setup_bk7258_sdk.sh` and `generate_bk7258_sdk_manifest.py` are deleted.
- Older SDK bundle support is removed from Python, Make, CMake, importer,
  registry, docs and tracked manifest/provenance. The ignored local old bundle
  directory was deliberately not deleted.
- Current SDK docs and active provenance contain no developer username or
  host-absolute path. Existing bundles remain truthfully identified as archive
  products rather than falsely attributed to a later Git checkout.

- New SDK behavior tests cover corruption, extra files, symlinks, duplicate

  project-memory structure checks pass.

## Remaining transition
