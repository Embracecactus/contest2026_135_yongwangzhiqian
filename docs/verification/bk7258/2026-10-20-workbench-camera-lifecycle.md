# 电脑相机工作台：预览生命周期与本地保存

日期：2026-10-20。此记录区分电脑端软件验证与实板验收。

## 使用方式

已有独立 camera 授权的电脑继续使用原生 USB、受保护 PC profile 和原有工作台命令：

```sh
python tools/bk7258/bk7258.py workbench serve --port NATIVE_PORT --profile PROTECTED_PROFILE --workbench-dir NEW_RECEIPT_DIR --listen-port 0
```

Windows 串口应由 Windows Python 打开；参数替换为已有配置，工作目录必须新建。
打开终端打印的本机链接；其中的会话令牌不要分享。

1. 点击“采一帧”。每次点击只采一帧，开始新取景即清除旧预览。
2. 等待图片解码显示后，点击“保存到本机”。下载的是已显示 JPEG，不再次采集或读取图片接口。
3. 再次点击“采一帧”可重新拍摄；“清除预览”删除浏览器的图片引用，在加载期间也可操作。
4. “取消采集 / 传输”只提交取消意图，等待设备释放确认；异常或结果未知不冒充成功。
5. “读取相机状态”和“释放设备缓存”不删除浏览器已下载的照片。已经显示的照片在设备断开后仍可保存或清除。
6. Ctrl+C 结束本地服务。默认不自动保存、不上传、不持续采集；本功能是单帧拍照。

## 数据与资源合同

`GET /api/state` 只返回元数据和 `preview_available`，不重复携带 JPEG。
浏览器对本次完成的任务调用一次 `POST /api/camera-preview`，正文为本地任务 `id`。
接口沿用原有 Host、Origin、Bearer 限制，不打开 USB、不发起采集；同一有效任务可再次显式读取。
只有 ready、valid 且设备缓存释放已确认的结果可发布图片。失效任务返回 410，非法输入 400，未授权 403。

服务只保留最近一张、最多 100 KiB JPEG 对应的 base64 内存副本，可读窗口 120 秒；
过期在下一次状态或图片请求时移除，新采集和服务关闭也会移除。图片不写磁盘。
浏览器图片与设备缓存生命周期独立，页面只有解码成功后才启用保存。
解码失败、过期、取消、启动失败或断线会明确反馈；随后相同终态轮询不会覆盖错误。
旧请求和旧图片 load 回调不能恢复已清除的预览。

采集开始请求也进入 `try/finally`：设备已受理但应答丢失时仍尝试按任务身份释放。
传输错误、超时、取消或未确认释放时不会发布成功图片。连接已断时无法确认远端释放，仍须回读。
相机继续要求独立 camera grant，tasks/resources/diagnostics 不代替相机权限。

## 实板边界与下一步

本轮已确认原生 USB 设备存在，但两次原有合法 profile 连接在 TLS 握手阶段结束，未发出相机命令。
15 秒只读串口观察记录到配置恢复错误 -12；它不能单独证明握手失败原因或固件身份。
`hil-connection.json` 保留失败类别和耗时。等待人工 RESET 后可重试，不重建 owner、不增加免认证入口。
当前设备运行版本因认证失败未重新核实；以前组合树的实板证据不能当成本独立候选证据。

连接恢复后按以下顺序验收并记录任务身份、字节数、SHA256、USB 传输耗时和点击至解码耗时，不保存真实照片：

1. 三次独立点击采集，每次确认有效 JPEG、释放确认及取消后的缓存为空。
2. 传输中主动取消，再采集；断开并重新建立连接后再采集。区分软件关闭会话和物理拔线。
3. 核对采集期间语音监听、动作采样、显示的退让和恢复，以及缓存申请/清零/释放。
4. 准入源码已检查：语音交互、OTA、显示资源占用等会阻止采集；失准入协作取消。动作有独立工作线程，但当前没有实板并发证据，不能据此宣称无采样干扰。

受影响软件测试可执行；上述实板项目目前阻塞。现有旧 16B 传输证据约 15 KiB / 76 秒，
它来自以前的组合设备会话，不能替代当前测量，也不足以承诺连续预览。
先完成实板预算，再评估 UVC 或 USB Audio，本轮不实现自动连续采集或新增 USB 设备类。
