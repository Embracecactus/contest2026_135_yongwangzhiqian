## 79 次快语速漏检的逐样本证据

读取上轮报告、`run_joint_old.py`、训练目标和实际 C 推理实现后，复用产品 C 的采集帧、前端、状态和事件判断，记录每 20 ms INT8 分数及每 300 ms 判定点，再将相同 C 特征输入浮点图。原样复现 21/100；没有降低 0.60 阈值、改变连续两次判定、0.20 释放阈值或 1000 ms 冷却。

| 用户要求的原因类别 | 已证实的统计与边界 |
|---|---|
| 音素/音节压缩 | 100 条均为完整目标音频的 `ffmpeg atempo=1.5`，波形支撑区间 885–1668 ms，中位 1305 ms。没有音素对齐标注，不能把其中任意漏检进一步断言为某个音素丢失。 |
| 词首/词尾截断 | 评测生成器变速完整目标音频，再加前后各 3 秒静音；原始超长目标被排除而非裁切。未发现评测代码主动截断证据，100 条均无 PCM 满幅削波。没有人工音素边界，语音学截断原因仍未确认。 |
| 特征/时间窗口 | **10/79** 在有效窗口中出现过 ≥0.60 分数，但不满足相邻两个 300 ms 决策点；其中 4 条高分峰完全未落到决策点，4 条只落到一个点，2 条落到两个不相邻点。 |
| 音量/SNR/发音变化 | 这组快语速条件未另加增益或环境噪声。无证据可将漏检归因于环境噪声；变速伪影和合成发音质量缺少音素标注，不能定量分摊原因。 |
| 模型快语速区分不足 | **69/79** 在整个有效窗口内 INT8 唤醒分数始终 <0.60，是直接失败原因；不等同于已经查明全部音韵学成因。 |
| 其他 | 浮点图也只有 19/100 满足连续判定；量化相对浮点救回 5 条、失去 3 条，量化不是这批 79 次漏检的主要原因。 |

69 + 10 是互斥的直接失败分类。其他行是证据边界或辅助实验，不重复累计。固定同一波形、保持判定相位，只将静音前缀设为 0/1200/3000 ms，100 条逐样本峰值和命中完全一致，排除了静音前缀长度这一假设。

B 修复了上述 10/10 时间确认失败及 24/69 分数不足；C 修复 10/10 和 26/69；均保留原先 21 个快语速命中。因此收益来自训练后的打分行为，不能解释成阈值调低。B/C 仍分别漏掉 45/43 个旧集快语速条件。

证据：逐样本统计（`out/wakeword-speed-20261026/fast-failure-analysis.json`）、20 ms 分数/判定点/浮点轨迹 NPZ（`out/wakeword-speed-20261026/fast-traces.npz`）、上下文对照（`out/wakeword-speed-20261026/context-ablation.json`）、追踪脚本（`out/wakeword-speed-20261026/diagnose_fast.py`）、前缀实验脚本（`out/wakeword-speed-20261026/diagnose_context.py`）。样本以哈希关联，未公开私人原音频或识别路径。NPZ 列依次为采集帧结束 ms、INT8 wake、是否 300 ms 判定点、浮点 wake；不是人工词尾标注。

## 训练设计与数据

A 是上轮 `out/wakeword-training-20261026/selected` 的原模型。其他组均从 A 的校验后浮点权重初始化，使用同一联合训练 manifest、seed=20261026、batch=64、Torch CUDA 及原 C PCAN v2 特征。保持 TCN32/k9/dilation 1,2,4,8,16、16 kHz mono PCM16、480 sample 窗/320 sample hop、40 维特征及运行时判定不变。

| 组 | 速度增强因子 | 目标完成后监督区间 | 学习率 | epoch / 最佳 epoch | 目的 |
|---|---|---:|---:|---:|---|
| A | 上轮已训练候选 | 600 ms | 上轮配置 | 本轮 0 | 不变基线 |
| B0-control | 0.75, 1.25, 1.5 | 600 ms | 1e-4 | 12 / 1 | 原数据配方继续训练对照 |
| B-multispeed | 0.65, 0.75, 1.15, 1.35, 1.5, 1.7 | 600 ms | 1e-4 | 12 / 7 | 保留正常/慢速并拓宽快语速 |
| C-hold800 | 与 B 相同 | 800 ms | 1e-4 | 12 / 7 | 针对 10 次短暂高分，仅改训练时间标签 |
| D-lr3e5 | 与 B 相同 | 600 ms | 3e-5 | 12 / 1 | 验证减小步长是否能抑制已有识别能力退化 |

每组保留负样本最大帧损失、完整目标后负尾段权重 0.1、词首/词尾不完整片段难负例、普通连续语音、按原说话音色/来源分配的正例权重，以及原始/小音量/冷热启动混合。C 的 800 ms 结束早于负尾段的 1000 ms 起点；不会增加设备冷却。D 未解决退化，保留失败结果。

基础训练集共 1194 条正例窗口（38 授权真实、1156 合成）、3136 unknown 和 88 silence；它们不是 1194 个独立说话人。所有速度/音量衍生样本留在原 source/speaker 的训练 split。B/C/D 实际训练派生窗口各 42389，B0 为 35225；扩增数量不能当成独立数据量。保留了可恢复 checkpoint、训练曲线、最佳权重、转换模型及每组 `experiment-config.json`。

数据身份与来源：训练清单（`out/wakeword-speed-20261026/training-data-list.json`）、固定配方（`out/wakeword-speed-20261026/training-recipe.json`）、D 配方（`out/wakeword-speed-20261026/low-lr-recipe.json`）、新留出计划（`out/wakeword-speed-20261026/holdout-plan.json`）、新音频来源/哈希（`out/wakeword-speed-20261026/holdout-provenance.json`）、泄漏与历史使用检查（`out/wakeword-speed-20261026/data-exposure-audit.json`）。

上轮 400 个条件在本轮明确降为**已暴露回归集**。新的测试在选型前生成并冻结：两种此前未使用的公开标准合成音色 af_bella/am_adam，各 20 个原音源，合计 40 音源 × 正常/小音量/慢/快 = 160 条条件；另取不在上轮联合 manifest 中的 800 条真人非目标及 80 条合成难负例。源/音色/文件哈希与训练验证集合无交叉，旧大库 `result.json` 也记录此前未运行最终 test。新正例由固定 `ni↓xau↓, ˈoʊpən ˈviː lɑː` token 路径生成；英文标准音色的混合语言发音仅为合成压力测试，尚无人类声学审核，不能冒充真人、口音或距离泛化。

复用 [Kokoro 官方 Apache-2.0 模型/音色](https://huggingface.co/hexgrad/Kokoro-82M/tree/f3ff3571791e39611d31c381e3a41a3af07b4987) 与已有 [Mobvoi/OpenSLR 87](https://www.openslr.org/87/) 授权素材；本轮仅补取两份公开音色包及其说明，未上传任何录音、购买服务或克隆个人音色。已有真实训练语音保持本地和原授权范围。新测试现已暴露，下轮不能再称其为未见测试。

## 复现与回滚

训练代码实际改动限于现有 `tools/bk7258/_lib/voice_kws.py`：新增 `--tempo-rates` 与 `--streaming-positive-hold-ms`，校验范围并绑定缓存/训练元数据；复用已有 CPU 特征、Torch CUDA、Keras 转换、INT8 导出和评测入口。不是新的训练平台。源快照见 trained-source（`out/wakeword-speed-20261026/trained-source`），每组配置和数据清单哈希可核对。

从工作区根目录，使用原环境（Python 3.10.12、Torch 2.12.1+cu130、TF 2.15.1、NumPy 1.26.4、RTX 5060）：

```bash
KWS_PY=out/kws-optimize-20261024/venv/bin/python
$KWS_PY out/wakeword-speed-20261026/run_speed_training.py
$KWS_PY out/wakeword-speed-20261026/run_low_lr.py
$KWS_PY out/wakeword-speed-20261026/evaluate_round.py A B0-control B-multispeed C-hold800 D-lr3e5
$KWS_PY out/wakeword-speed-20261026/native_round.py A B0-control B-multispeed C-hold800 D-lr3e5

$KWS_PY out/wakeword-speed-20261026/evaluate_holdout.py
python3 out/wakeword-speed-20261026/build_results.py
```

上述是首次执行顺序；已存在模型/评测/包会跳过或拒绝覆盖。要真正重训，复制实验脚本到新的 `out/wakeword-speed-REPRO/`，先生成/冻结留出集，使用每组 `experiment-config.json` 的完整参数和相同输入哈希，输出写入新目录。`freeze_experiments.py` 绑定每组配置/数据/源码。新语音生成命令使用同一 `KWS_PY`，并设置 `USE_TF=0 PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES='' PYTHONPATH=out/kws-optimize-20261024/large-positive/python-deps` 后执行 `prepare_holdout.py`；前两次生成启动分别因错误解释器缺 Torch、NumPy 与 TF ABI 混载失败，第三次以该环境完成，失败日志保留，未改训练依赖或系统安装。
