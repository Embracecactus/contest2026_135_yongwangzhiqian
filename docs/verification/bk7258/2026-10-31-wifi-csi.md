# 2026-10-31 AIDK 真实 CSI 数据质量验证

本轮已在傻妞 AIDK AI Toy 上打通 SDK 原始 CSI 回调、NuttX UDP 导出和电脑记录。
最终 60 秒会话收到 1,379 帧，全部为 48 个原始 32 位采样字；依据终态计数，
本次从 UDP 栈接受到主机接收之间没有缺帧。用户本轮不便配合人工场景，全部记录
标记为 `unlabeled`，没有人体存在、静坐或运动检测准确率结论。

## 实现与构建

- 独立 `csi_cp` / `csi_ap` 诊断组合，使用现有 fixed-block CSV 和 direct 启动；
  普通语音 profile 不启用 CSI。CP SDK 增加 `cp-aidk-csi` profile。
- 回调只校验、复制实际长度；AP 既有 Wi-Fi worker 管理队列、限时采集、计数和
  UDP。CP 通过既有控制链提供 `bkwifi csi start/status/stop`。
- 主机唯一入口 `tools/bk7258/bk7258.py csi receive/analyze` 保留原始数据报，
  支持独立空房标定的实验性幅度评分和 RuView ADR-018 转发。此处没有运行
  RuView 推理服务，也没有验证其模型在 BK7258 数据上的效果。
- SDK 固定为 `v3.1.1.9`，revision
  `eb0d4252a83f0ba88f0eb947fcfa2e36cbcb9bb4`；CSI CP bundle 内容树 SHA256 为
  `79385513527710bc565361b7d9a1c68099da8557a2d17e2829f12fb2c7168c33`。
- 增量 CP/AP 构建及 layer gate 通过。最终 AP resolved config 启用
  `CONFIG_NET_SOLINGER=y`，socket 关闭等待有一秒上限。
- CSI 主机回归 6 项通过，包含真实 C 适配层的模拟边界检查、C/Python 协议互通、
  接收器和计数分析；既有 Wi-Fi 异步 5 项及原生网络租约 1 项通过。
  主机检查不替代以下实板证据。

## 实板观测

采集前显式关闭 STA 省电是本次打通回调的关键：此前没有有效回调，关闭省电后
60 秒探测得到 1,405 次回调。电脑 WLAN 地址的直连路径出现 ARP 不通和
`ENETUNREACH`；改用电脑可路由的有线地址后收包成功。经过 NAT 的收包源地址
与设备 DHCP 地址不同，因此记录器没有按设备 DHCP 地址过滤。

最终请求为 60,000 ms、间隔 40 ms、format=3；实际返回均为 NON_HT 原始数据。
请求间隔不保证每个间隔都有回调，回调之前的无线丢帧率仍然未知。

| 指标 | 60 秒会话结果 |
|---|---:|
| 设备回调 / UDP 接受 / 主机唯一数据帧 | 1,379 / 1,379 / 1,379 |
| 有效长度 / 类型 | 全部 48 words / `data_type=0` |
| 主机实测平均帧率 | 23.322 Hz |
| SDK 时间间隔中位数 / 标准差 | 40.199 / 10.878 ms |
| SDK 时间间隔 P95 / 最大值 | 78.627 / 161.520 ms |
| 无效回调 / 队列丢弃 / 发送错误 | 0 / 0 / 0 |
| UDP 接受后至主机的缺帧 / 重复 | 0 / 0，收到完整终态计数 |
| 不同的原始采样数组 | 1,379 / 1,379 |
| 解码分量非零占比 | 99.9547% |

终止接收门后先排空队列、发送三次终态水位，再调用 SDK 停止接口。
完整串口捕获的 10 秒与后续 60 秒会话均成功停止；后者保留 session=2、
callbacks=sent=1379、active=0，AP 为 HEALTHY，faults/recoveries=0/0，STA 保持连接。

早期短采集后的查询曾出现 session 清零、心跳回退的重启迹象；后来完整串口
捕获和连续两次会话未复现，原因没有确认。因此不宣称诊断固件通过长期稳定性
验收，保留这些早期日志供后续定位。

## 恢复与验收边界

用户批准临时 CSI 诊断并恢复原语音固件，随后明确免除本轮实时读回。
恢复复用已核对哈希的同板历史 CP/AP 产物，仅写主、备 CP/AP 软件范围；
启动区、配置、身份和校准数据均不在写入范围。没有声称获得新的全片读回副本。
同板恢复 payload 的独立副本和哈希保存在本地证据目录 `rollback/`。

恢复已完成：BK Loader 必需成功标记齐全，没有终止失败标记；其进程退出码 1
按该工具约定只作参考。恢复后的新串口记录确认设备身份摘要与开始前一致，
AP 为 HEALTHY，CPU2 在线，Wi-Fi 已连接，未见 HardFault/ASSERT/panic。
语音按钮任务存在；本轮没有做扬声器到麦克风的语音实测。
恢复证据为本地 `restore-command.json`、`restore.log`、`restore-result.json`、
`restored-boot/serial.raw` 和 `restore-boot-result.json`。

本轮只完成数据链路和质量验证。空房、静坐、走动的独立对照及检测指标尚未
采集；呼吸、心率、动作识别、相位标定与姿态重建均未验收。
